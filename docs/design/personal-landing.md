# 개인 랜딩 페이지

| 항목 | 값 |
|---|---|
| 상태 | 더미 콘텐츠 시안 구현 |
| 추적 | [개인 랜딩 페이지 방향 결정](https://github.com/woonyong-choi/homepage/issues/13) |

최신 기록 탐색과 보존 영역의 결정은 [기록 탐색과 화면 구성](knowledge-navigation.md)을 따른다. 아래 랜딩 시안의 내용과 충돌하면 해당 문서를 우선한다.

## 요약

사용자 자신을 제품으로 소개하는 SaaS 랜딩 페이지를 구성한다. 소개 문구는 함께 일할 때 제공하는 가치를 설명한다. 사용자 출연 영상은 말하고 설명하는 모습을, 프로젝트는 구현 결과를, 동료 평가는 협업 경험을 보여준다. 블로그와 위키는 생각과 지식을 더 읽는 경로로 연결한다.

사용자 지시에 따라 동료 평가 카드와 출연 영상은 각각 별도의 가로 띠에서 오른쪽에서 왼쪽으로 반복 이동한다. 출연 영상과 프로젝트 시연은 콘텐츠 종류를 구분한다. 프로젝트 화면 녹화를 사용자 출연 영상으로 대체하지 않는다.

## 동기

문서형 메인은 지식 탐색에 강하지만 방문자가 구현 결과와 개인 기여를 발견하기까지 여러 번 이동해야 한다. 새 첫 화면은 짧은 데모를 통해 작업의 결과를 먼저 보여주고, 상세 프로젝트에서 설계와 검증을 설명한다. 이력서와 연락 링크는 상단에서 바로 찾는다.

기존 문서형 UI는 `feat/11-repo-profile-preview`의 `c729da0`에 보존한다. 해당 커밋은 가져온 테마 스냅샷도 포함하므로 단독 복구가 가능하다. 테마 정본의 대응 커밋은 `9bc2487`이다. 새 조사 브랜치는 기존 커밋에서 분기하며 기존 미리보기의 공개 출력은 유지한다.

## 예시

### 구현 결과를 먼저 본다

1. 방문자는 한 문장 소개와 대표 데모를 본다.
2. 큰 영상 한 개와 작은 영상 두 개가 음소거로 반복 재생된다.
3. 각 영상 아래에서 도구 이름, 시연 기능, 본인 기여를 읽는다.
4. 영상을 선택하면 자동 미리보기가 멈추고 조작 가능한 상세 플레이어가 열린다.
5. 프로젝트 상세에서 문제, 역할, 구현, 검증과 한계를 확인한다.

### 협업 경험을 확인한다

1. 방문자는 왼쪽으로 흐르는 동료 평가 카드에서 실제 평가 문구를 읽는다.
2. 카드에 마우스를 올리거나 키보드 초점을 두면 해당 띠가 멈춘다.
3. 작성자 표기, 함께한 프로젝트와 역할을 확인한다.
4. 전체 평가를 열면 원문을 읽고 관련 프로젝트로 이동할 수 있다.

### 사용자 출연 영상을 본다

1. 방문자는 발표·인터뷰·협업 등 사용자가 실제로 등장하는 영상 띠를 본다.
2. 화면에 보이는 짧은 클립들이 음소거로 반복 재생되며 왼쪽으로 흐른다.
3. 카드에 마우스를 올리면 이동만 멈추고 영상 미리보기는 이어진다.
4. 카드를 선택하면 이동과 배경 재생이 멈추고 원본 플레이어가 열린다.
5. 원본 플레이어는 소리와 자막을 조작할 수 있다. 닫으면 기존 카드에 초점이 돌아온다.

### 움직임을 줄여 읽는다

1. 방문자는 전체 영상 일시정지를 누른다.
2. 영상들은 현재 화면 또는 포스터로 멈추고 글과 링크는 그대로 남는다.
3. 움직임 감소 설정이나 자동재생 차단 환경에서는 포스터와 재생 버튼이 먼저 나온다.

## 상세 설계

### 현재 시안

사용자가 Things를 새 기준으로 지정했다. 현재 구현은 라이트 모드, 중앙 정렬 소개, 프로젝트·블로그·위키 입구, 정적인 평가 두 개로 구성한다. 자동 이동과 자동 영상 미리보기는 제거하고 소개 영상을 눌렀을 때만 재생한다. 상세는 [시안 설명](../../landing/README.md)에 있다.

아래 움직이는 띠 설계는 이전 제안의 기록이며 현재 구현에는 적용하지 않는다. 실제 자료 연결보다 더미 시안의 시각적 검토를 먼저 진행한다.

### 화면 순서

| 순서 | 방문자의 질문 | 내용 |
|---|---|---|
| 첫 화면 | 함께 일하면 어떤 가치를 얻는가 | 큰 한 문장 소개, 짧은 설명, 사용자 대표 영상, 프로젝트·연락 링크 |
| 동료 평가 | 함께 일한 사람들은 어떻게 말하는가 | 실제 평가 카드가 왼쪽으로 흐르는 띠, 작성자·협업 맥락·전체 보기 |
| 출연 영상 | 어떻게 설명하고 소통하는가 | 실제 출연 클립이 재생되며 왼쪽으로 흐르는 별도 띠, 제목·행사·원본 보기 |
| 대표 프로젝트 | 어느 부분을 맡았고 왜 그렇게 만들었나 | 문제, 개인 역할, 주요 선택, 실제 결과, 상세 사례 링크 |
| 글과 위키 | 생각과 지식을 더 볼 수 있나 | 대표 기술 글, 언어·프레임워크별 위키 입구 |
| 연락 | 어떻게 다음 대화를 시작하나 | 이력서, 공개 연락 경로, GitHub |

첫 화면의 소개 예시는 “문제를 이해하고, 함께 쓸 수 있는 도구로 만듭니다.”이다. 실제 경험의 근거와 대조해 확정한다. 문서형 버전에서 정한 블로그 우선 순서는 그 버전에 남긴다. 이 분기에서는 사용자 소개, 동료 평가, 출연 영상으로 인물과 협업 경험을 먼저 전달한다.

### 움직이는 띠

- 평가와 영상은 각각 가로 한 줄을 기본으로 한다. 위에서 아래로 쌓이는 자동 스크롤이나 페이지 전체의 자동 이동은 사용하지 않는다.
- 양끝의 카드가 일부 잘려 다음 카드가 있음을 보여준다. 가장자리 효과는 글과 재생 조작을 가리지 않는다.
- 같은 카드를 이어 붙여 마지막에서 처음으로 돌아갈 때 끊김이 보이지 않게 한다. 시각적 복제본은 접근성 트리와 키보드 탐색에서 제외한다.
- 카드 수가 적어 띠를 채우지 못하면 같은 평가가 동시에 반복 노출되지 않도록 정적 정렬한다.
- 각 띠에 정지·재개와 이전·다음 조작을 제공한다. 터치 환경에서도 자동 이동을 멈춘 뒤 수동으로 탐색할 수 있다.
- 마우스 진입과 키보드 초점은 해당 띠의 이동을 멈춘다. 사용자가 명시적으로 정지한 상태는 마우스가 벗어나거나 스크롤해도 해제하지 않는다.
- 탭이 비활성화되거나 띠가 화면 밖으로 나가면 이동과 미리보기 재생을 멈춘다. 다시 보일 때는 사용자 정지 상태를 확인한 뒤 재개한다.
- 움직임 감소 설정에서는 정적 카드와 수동 재생을 기본으로 한다. 별도의 전체 움직임 정지 버튼은 두 띠와 배경 영상을 함께 제어한다.
- 이동 속도·카드 폭·간격은 공통 테마 토큰으로 관리한다. 두 띠의 리듬은 구분하되 실제 글 길이와 영상 용량을 확인하기 전에 임의의 최적 속도를 확정하지 않는다.

### 영상 동작

- 상단 대표 영상과 출연 영상 띠를 별도로 둔다. 화면에 들어온 클립들이 함께 재생되도록 하되 실제 기기에서 동시 재생 개수를 검증한다.
- 각 클립은 한 동작을 보여주는 짧은 구간으로 편집한다. 초기 편집 목표는 8~15초이며 측정된 최적값은 아니다.
- `<video muted loop playsinline>`으로 재생을 요청한다. 브라우저의 허용 여부는 별도로 처리한다. [MDN 자동재생](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)
- 화면에 들어온 영상만 재생하고 나가면 멈춘다. 비활성 탭에서는 모두 멈춘다. [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)
- 사용자가 누른 전체 정지는 스크롤로 해제하지 않는다. 상세 플레이어에서는 배경 영상을 정지하고 사용자가 소리를 켠다.
- 자동재생 실패, 영상 로딩 실패, 움직임 감소 설정에서는 포스터와 재생 버튼을 유지한다. [움직임 감소 설정](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
- 반복 클립은 화면 아래에서 원본 다운로드를 계속하지 않도록 로딩 범위를 제한한다. 긴 설명 영상과 짧은 미리보기 파일을 분리한다.
- 휴대폰 자동재생·절전 모드·동시 디코딩은 실제 기기 검증 대상이다. 데스크톱 미리보기만으로 재생 성공을 주장하지 않는다.

### 제작 도구

현재 정적 사이트에 HTML video, CSS, Intersection Observer를 우선 사용한다. 스크롤 연동이나 전환이 복잡해질 때 [Motion의 JavaScript API](https://motion.dev/docs)를 검토한다. 이 구성 때문에 React나 Next.js로 바꿀 필요는 없다.

[Screen Studio](https://screen.studio/)는 실제 데모 녹화·커서 확대·편집용 후보다. 설치나 구매 없이 기존 녹화 파일로도 시작할 수 있다. 영상 호스팅 서비스는 파일 수·용량·트래픽을 확인한 뒤 정하며 첫 단계에서 새 서비스 종속성을 만들지 않는다.

### 콘텐츠 조건

| 자료 | 필요한 내용 | 없는 경우 |
|---|---|---|
| 출연 영상 | 사용자 본인 등장 여부, 제목·행사 맥락, 원본 URL, 미리보기 클립·포스터·자막 | 제품 시연이나 다른 사람 영상으로 대체하지 않음 |
| 데모 | 실제 녹화, 기능 설명, 본인 구현 범위, 공개 가능한 화면 | 새로 촬영하며 다른 서비스 영상을 본인 작업처럼 사용하지 않음 |
| 프로젝트 | 문제, 역할, 구현, 저장소 또는 공개 결과, 검증 범위 | 확인된 항목만 표시 |
| 동료 추천 | 원문, 작성자 표기, 함께한 역할, 공개 동의 | 추천 영역을 숨김. 가상 별점·인물·칭찬을 만들지 않음 |
| 연락 | 공개 가능한 연락 경로와 이력서 | 확인된 GitHub 링크만 표시 |

추천글은 앱 리뷰의 시각적 형식을 활용하되 별점이나 고객 수를 개인에게 임의 적용하지 않는다. 긴 추천은 발췌 여부를 밝히고 전체 보기로 연결한다. 기본 표현은 사용자가 지정한 왼쪽 방향의 움직이는 띠다. 정적 카드는 자료 부족·움직임 감소·사용자 정지에 대한 대체 표현이다.

위키의 개인·커리어·프로젝트 문서와 연결된 로컬 발행 자료에서 동료 평가 및 출연 영상 원문을 탐색했다. 현재 조회 범위에서는 본인에 대한 평가 원문과 본인 출연을 확인할 수 있는 영상 주소를 찾지 못했다. 다른 동료의 면접 자료와 관계 기록은 사용자에 대한 추천으로 사용하지 않는다. 화면 구현 여부와 실제 콘텐츠 연결 여부는 별도로 보고한다.

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 원본 문서형 시안을 복구할 수 있다 | 보존 커밋의 소스·테마 스냅샷과 원격 브랜치 확인 |
| 영상으로 기능과 개인 기여를 식별한다 | 데모 아래 문구와 프로젝트 근거 대조 |
| 여러 영상의 재생을 직접 통제한다 | 가시성, 전체 정지, 상세 열기, 탭 비활성, 자동재생 거절 검사 |
| 추천이 실제 협업을 반영한다 | 인용 원문, 표기와 공개 범위 대조 |
| 두 띠가 왼쪽으로 흐르며 독립적으로 멈춘다 | 이동 방향·반복 경계·마우스·키보드·터치·정지 유지 검사 |
| 출연 영상에서 본인을 식별한다 | 영상 원본과 등장 구간 확인, 프로젝트 시연과 구분 |
| 읽기와 탐색이 유지된다 | 키보드, 모션 감소, 포스터 실패 대체, 위키 이동 검사 |
| 미리보기에 허용한 자료만 공개한다 | 기존 allowlist export를 새 페이지·승인된 미디어에 한정해 확장 |

## 단점

영상과 추천 원문이 빈약하면 랜딩의 설득력도 제한된다. 큰 미디어는 전송량과 디코딩 비용을 늘리고 여러 자동재생 영상은 읽기를 방해할 수 있다. 실제 기기 측정과 일시정지 기능을 수용 조건으로 둔다.

## 대안

기존 문서형 메인은 보존된 브랜치에서 계속 비교할 수 있다. Readymag처럼 강한 색과 작품 벽을 전면에 두는 방식은 개인 기여를 설명하는 공간이 줄어 보조 참고로 한정한다.

## 미해결 질문

- 위키의 실제 동료 평가 문서와 사용자 출연 영상 원본 위치 확인이 필요하다 ([#13](https://github.com/woonyong-choi/homepage/issues/13)).
- 동료 추천 원문과 공개 가능한 이름·역할·인용 범위가 준비되어 있는지 ([#13](https://github.com/woonyong-choi/homepage/issues/13)).
- 동시 재생 개수와 미디어 용량을 휴대폰·데스크톱에서 어느 수준으로 수용할지 ([#13](https://github.com/woonyong-choi/homepage/issues/13)).
- 후속 구현은 미디어 상태 처리와 랜딩 UI를 포함한다. 공개 데모·추천 자료가 정해지면 별도 구현 이슈로 연결한다 ([#13](https://github.com/woonyong-choi/homepage/issues/13)).
