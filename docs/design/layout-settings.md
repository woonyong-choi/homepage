# 영역 설정

| 항목 | 값 |
|---|---|
| 상태 | 구현 |

## 요약

공개 Blog의 문구와 카드 표시 정책을 작성 설정으로 관리한다. 색·글꼴·간격·반응형과 공통 동작은 design-tokens가 소유한다.

## 해결하는 문제

글의 표시 여부와 순서를 바꾸는 설정이 디자인 값을 중복하지 않게 한다. 공개 Blog 설정과 개인 위키 호스트의 기존 설정을 분리한다.

## 사용 예

### 사용 장면

썸네일이 없는 글도 제목 표지를 자동으로 표시한다. Search 카드는 제목·설명·날짜를 보여 주며 태그는 필터와 본문에서 사용한다.

## 작동 방식

### 승인 설정

설정은 Vault에서 수정·승인한 뒤 [발행 목록을 동기화](publication.md#vault-발행-입력)한다. `content/home.md`, `config/site.json`, `config/search.json`, `config/blog.json`, `config/tags.json`은 승인 사본이며 직접 수정하지 않는다.

`config/cs.json`, `config/tech.json`은 Vault 발행 목록이 요구하는 동기화 호환 입력으로 보존하며 홈페이지 코드는 내용을 읽지 않는다. `content/pages/tech.md`의 `topics`는 개인 위키 미리보기의 분류 검사 입력으로 보존한다. 공개 Blog의 필수 분류나 허용 목록으로 사용하지 않는다. 홈페이지에서 이 사본을 고쳐 새 공개 모델을 만들지 않는다.

### 홈과 Blog

공개 상단 탐색은 Search `/search/`와 Blog `/blog/`다. Search는 전체 글의 목록·검색·태그 필터이고 Blog는 같은 글을 최근 날짜순 본문으로 보여 준다. 홈 원고의 기존 탐색 값은 개인 미리보기 호환을 위해 보존하며 공개 페이지 조립이 목적지를 정한다. 홈의 기술 로고는 현재 발행 글에 존재하는 실제 태그 ID의 검색 필터로 연결한다. 서비스 키, 브랜드 표시명, 등록된 별칭을 대조하며 서비스 키 정확 일치, 표시명 정확 일치, 대소문자 무시 일치, 별칭 일치 순으로 하나를 선택한다. 같은 순위는 태그 ID순이다. 여러 별칭 태그를 합치거나 다중 AND 필터로 바꾸지 않는다. 공개 글이 없어도 기술 섹션의 제목과 소개는 유지한다. 설정된 기술 로고도 유지하며 일치하는 발행 태그가 없는 로고는 링크 없이 비활성 상태로 표시한다. 발행 또는 글 제외 때마다 활성 여부를 다시 계산한다.

공개 빌드와 개인 미리보기가 함께 쓰는 로더 `loadBlogLayout`은 `config/blog.json`의 `title`, `collection`, `card`, `feedSize`, `autoLoad`, `archiveLabel`과 `config/search.json`의 `title`, `box`를 읽는다. `cs`, `tech`, 검색 입구의 `sections`를 필수 입력으로 요구하지 않는다. `feedSize`는 Blog의 페이지당 본문 수이고 `autoLoad`는 다음 페이지 자동 추가 여부다. `archiveLabel`은 Search 전체 글로 이동하는 문구다. 기존 `preview`, `archiveTitle`, `feedLabel`은 별도 공개 목록을 만들지 않는다.

`collection.columns`, `collection.rows`는 목록 배치와 한 페이지의 항목 수를 정한다. `rows: null`은 필터 결과 전체를 한 페이지로 표시한다. 카드의 `title`, `description`, `tags`, `date`, `comments`는 각 항목의 표시 여부다. 선택 항목 `author`(기본 `false`)를 켜면 `config/site.json`의 `name`과 선택 사진 `avatar`를 카드 아래와 글 도입문 아래의 글쓴이 줄에 표시한다. 카드 태그는 앞의 3개만 보인다. `media: image`는 지정한 대표 이미지, 없으면 본문의 첫 공개 그림을 카드 표지로 쓰고, 둘 다 없으면 제목으로 표지를 자동으로 만든다. `icon`, `none`은 공개 글의 장식 이미지를 만들지 않는다. 같은 표시 정책을 정적 목록과 검색 뒤 다시 그린 목록에 적용한다. 실제 글 포함 여부는 승인·공개 상태·발행일·빌드 모드로 정하며 카드 설정 때문에 글을 제외하지 않는다. 자동 표지는 카드에만 표시한다.

검색어와 태그, 페이지는 `q`, 반복 `tag`, `page`로 `/search/`에 저장한다. 검색창은 공통 구성 요소를 사용하며 검색어와 태그의 AND 조건은 표시 설정으로 바뀌지 않는다. 목록·검색·태그는 같은 공개 글 집합을 사용한다. 분야별 목록은 만들지 않는다. Blog 본문 피드는 같은 글 집합과 `feedSize`, `autoLoad` 설정을 사용한다.

### 공통 디자인

카드 배치·이미지 비율·설명 줄 수·호버·초점·모바일 배치는 공통 카드 계약을 따른다. 홈페이지 문서에 CSS 치수를 복제하지 않는다. 바꿀 위치와 의존성 갱신은 [스타일 수정 지도](styles.md)에 있다.

Search 카드의 기본값은 `card.tags: false`, `card.author: false`다. 이 사이트는 2열, 태그·글쓴이 표시를 켠다. `card.media: image`이면 직접 지정한 대표 이미지, 본문 첫 그림, 공통 제목 표지 순서로 표시한다. `none`이면 표지를 생략한다. 카드 설명은 작은 보조 글자 크기를 사용하고 본문 태그는 `medium` 크기를 사용한다.

카드 제목은 한 줄, 설명은 두 줄을 넘으면 말줄임한다. 설명은 한글 어절을 묶지 않고 카드 폭을 사용한다. 날짜는 왼쪽, `댓글 · N` 표시는 오른쪽 끝에 둔다. 댓글 수가 미확인이면 숫자 대신 `댓글 보기` 링크를 표시한다. 댓글 아이콘은 사용하지 않는다. Search 제목에는 아이콘을 붙이지 않는다. 본문 태그는 하늘색 배경·파란 글자를 사용하며 호버 시 파란 배경·흰 글자를 사용한다. 검색 태그는 기본보다 진한 하늘색 배경의 호버와 진한 파란 배경·흰 글자의 선택을 구분한다. 호버 글자색도 함께 조정해 대비를 유지한다.

Search의 태그는 검색창·추천 검색어 아래와 제목 위에 중앙 정렬한 알약 토글이다. 선택한 모든 태그와 검색어에 맞는 전체 글에서 후보 태그를 계산한다. 선택된 태그는 결과가 없어도 표시해 해제할 수 있게 한다. 제목 아래에는 태그나 별도 선택 조건 줄을 두지 않는다.

태그를 선택하면 줄 끝에 파란색 밑줄의 초기화 링크를 표시한다. 초기화는 검색어·선택 태그·페이지를 모두 지우고 전체 글로 돌아간다. 선택 태그가 없으면 이 링크를 표시하지 않는다.

서비스 태그 후보 목록은 로고 정본의 브랜드 목록과 홈페이지 보유 로고에서 생성한다. 이름·표시명·별칭을 한 레지스트리로 조립하며 일반 태그의 허용 목록으로 쓰지 않는다. 빌드 결과 `/service-tags.json`은 모든 후보와 실제 발행 태그, 활성 여부, 흐름 포함 여부를 제공한다. 비활성 후보도 레지스트리에 보존하며 설정된 로고는 비활성이어도 흐름에 포함된다. 홈 원고에 지정한 항목을 기존 순서대로 표시하고, 나머지 활성 후보를 ID순으로 뒤에 추가하며 중복은 제거한다. 기술 섹션이 여러 개면 각 흐름이 같은 발행 태그 규칙을 사용한다. 비활성 섹션은 생략하고 빈 항목 목록에는 로고를 자동 추가하지 않지만 제목과 소개는 유지한다. 새 로고가 정본에 등록되면 다음 빌드의 후보 목록에 반영된다.

흐르는 목록의 동작은 공통 `FlowRail`이 소유한다. 로고 묶음이 가용 가로 폭과 같거나 작으면 중앙에 고정하고, 폭을 초과할 때만 반복 이동과 가장자리 페이드를 사용한다. 화면 크기나 목록 폭이 바뀌면 다시 측정한다.
