# 글 관리

사이트 화면은 그대로 두고, 관리자로 로그인한 브라우저에만 글 관리 기능을 얹는다. 배치와 흐름은 벨로그의 작성 흐름을 따르고 색·글꼴·크기·곡률은 공통 디자인을 쓴다. 사이트는 서버 없는 정적 사이트이므로 로그인은 GitHub 계정, 저장은 글 원본 저장소(비공개 Vault)에 커밋하는 것으로 대신한다.

## 화면

| 위치 | 관리자에게 보이는 것 |
|---|---|
| 모든 페이지 오른쪽 아래 | 동그란 + 단추(새 글)와 그 위의 임시·비공개 글 단추(개수). 누르면 사이트에 없는 글 목록이 뜨고 항목마다 임시저장·비공개·사이트 반영 안 됨을 표시한다 |
| 글 화면 | 글쓴이 줄 끝의 수정·삭제 |
| 작성 화면 | 왼쪽은 제목, 태그 칩(Enter·쉼표로 추가, 누르면 삭제, 한글은 NFC로 맞춤), 서식 단추, 본문. 오른쪽은 사이트 글 화면과 같은 `PostArticle` 실시간 미리보기. 본문은 문서 렌더러의 브라우저 출력(`src/document/preview/index.js`의 `renderPreview`)으로 사이트와 같은 규칙으로 그린다(그림 문단은 둥근 그림, 코드 펜스는 코드 블록). 코드 강조와 도표 그림은 배포 뒤 사이트에서 보인다. 아래 막대는 나가기·삭제(저장된 글만)·임시저장(비공개 글은 비공개 그대로 저장)·출간하기(공개 글은 수정하기만) |
| 출간 화면 | 사이트 목록 카드와 같은 `BlogCard` 미리보기와 요약 칸(150자), 공개 설정(전체 공개·비공개), 주소 이름, 발행일, 취소·출간하기. 썸네일은 고르지 않는다 |
| `/admin/` | 빈 화면 가운데에 사이트 로고와 로그인만 둔다. 로그인 서버가 없으면 GitHub 토큰 칸·로그인·토큰 만들기, 있으면 GitHub로 로그인 단추다 |

방문자에게는 1KB 남짓한 로더만 내려가고 아무것도 보이지 않는다. 작성 기능(`admin-editor.js`)은 로그인한 브라우저에서만 불러온다.

## 글 상태

| 상태 | 글 머리 | 사이트 |
|---|---|---|
| 임시 | `visibility: draft`, `status: draft`, `publish: false` | 싣지 않음 |
| 비공개 | `visibility: private`, `status: published`, `publish: false` | 싣지 않음 |
| 공개 | `visibility: public`, `status: published`, `publish: true` | 실음 |

- 임시저장은 주소가 없으면 `draft-날짜-임의값` 임시 주소로 저장한다. 출간할 때 정한 주소로 파일 이름과 `id`·`slug`를 바꾼다.
- 출간할 때 주소 이름 `all`·`page`·`feed`(사이트 목록 주소, `RESERVED_SLUGS`)와 오늘 이후 발행일은 막는다(비공개 저장은 막지 않는다). 다른 곳에서 미래 날짜로 공개한 글은 목록에 "발행일 전"으로 보인다. 저장 중에는 저장된 글을 다시 열 수 없다. 사이트는 오늘 이후 날짜의 글을 싣지 않고 예약 출간은 없다.
- 글을 열 때마다 작성 회차를 바꾼다. 앞 회차의 저장·그림 올리기가 늦게 끝나면 글 목록만 고치고 지금 연 글과 본문은 건드리지 않는다.
- 공개 글은 임시저장으로 사이트에서 내리지 않는다. 작성 화면의 단추가 수정하기 하나가 된다. 출간 화면에서 비공개로 바꾸면 사이트에서 내리고 배포한다.
- 작성 화면이 열려 있고 바뀐 내용이 있으면 1분마다 자동으로 임시저장한다. 임시·비공개 글은 그 상태 그대로 저장하고, 공개 글은 저장이 곧 배포이므로 자동 저장하지 않는다. 저장은 한 번에 하나만 하며 저장하는 동안 고친 내용은 다음 저장에 넣는다.
- 출간·수정·삭제한 공개 글은 사이트 저장소의 승인 사본을 한 커밋으로 맞춘 뒤(아래 사이트 반영) 배포 작업(`config/admin.json`의 `deploy`)을 실행하고 끝날 때까지 알림으로 알린다. 임시저장은 Vault에만 저장하고 배포하지 않는다.
- 사이트 반영은 `src/admin-site.mjs`가 맡는다. 글 사본(`content/blog`), 글이 쓰는 그림(`content/assets`)과 그 출처 기록(`config/assets.json`, `user-provided`), 승인 목록 해시를 사이트 저장소 main의 마지막 커밋 위에 한 커밋으로 얹는다.
- 연결이 끊기거나, 그사이 다른 커밋이 들어와 빨리 감기가 거절되거나(422), GitHub 일시 오류(5xx)면 최신 상태를 다시 읽어 3번까지 시도한다. 권한 없음(403·404)은 다시 시도하지 않고 안내한다.
- 공개 글 중 승인 목록의 해시와 내용이 다른 글은 "사이트 반영 안 됨"으로 목록에 남고, 관리 화면을 열 때 자동으로 한 커밋으로 다시 올린 뒤 배포한다. 열어서 수정하기를 눌러도 바꾼 내용 없이 다시 올린다.
- 글이 쓰는 그림은 사이트 빌드처럼 해석한 문서의 그림·링크 주소 중 `../assets/`·`assets/`·`/assets/`를 가리키는 것과 글 머리 썸네일만 센다(`src/post-assets.mjs`). 코드 블록·외부 주소는 세지 않고 한글·괄호·하위 폴더 이름도 그대로 옮긴다. Vault에 없는 그림이면 그 글의 반영만 실패로 알린다.
- 공개 글 삭제는 세 단계다: Vault에서 비공개로 바꾸기 → 사이트에서 내리기 → Vault에서 지우기. 어느 단계에서 멈춰도 Vault와 사이트가 어긋나지 않고, 마지막 단계만 실패하면 비공개 글로 목록에 남는다(삭제한 글이 자동 맞춤으로 다시 올라가지 않는다). 사이트에서 내렸으면 마지막 단계가 실패해도 배포한다. 임시·비공개 글은 바로 지운다.
- 공개에서 임시·비공개로 바꾸면 Vault를 먼저 바꾸고 사이트에서 내린다. 내리지 못한 사본(Vault에서 임시·비공개가 된 글, 같은 주소가 다른 파일 이름으로 옮겨진 글의 옛 사본)은 관리 화면을 열 때 자동으로 내린다. 옛 사본은 파일 이름이 아니라 사본 글 머리의 주소로 판단하고, 같은 주소의 새 사본 올리기와 한 커밋으로 묶는다. Vault에 같은 이름도 같은 주소도 없는 사본은 다른 경로로 올린 것일 수 있어 건드리지 않는다.
- 사이트 반영은 한 번에 하나씩 차례로 하며, 자동 맞춤은 글마다 따로 해서 한 글이 실패해도 나머지는 맞춘다. GitHub API 응답은 브라우저 캐시를 쓰지 않는다(60초 캐시 때문에 예전 내용을 읽지 않게).
- 배포 완료는 실행 전 마지막 배포 번호보다 나중에 생긴 실행으로 판단한다. 실행 전 목록을 못 읽으면 결과를 기다리지 않는다. 배포를 기다리는 동안(최대 몇 분)에도 다른 글을 열고 고칠 수 있다.
- 바뀌거나 지운 글이 예전에 쓰던 그림 중 다른 공개 파일(글·원고·설정)이 쓰지 않는 그림은 같은 커밋에서 파일·승인 해시·출처 기록을 함께 지운다.
- 발행일과 "오늘 이후 글" 판단은 한국 날짜(`Asia/Seoul`)로 한다. UTC로 비교하면 한국 0시~9시에 오늘 날짜 글이 빠진다.
- 썸네일은 글 머리에 이미 적힌 그림, 본문의 첫 그림, 제목으로 만든 표지 순서로 정한다. 사이트 목록 카드도 같은 순서다.
- 요약(`description`)은 목록 카드와 글 머리에 보이는 글이다. Obsidian에서 글 머리에 쓴 요약을 출간 화면의 요약 칸에서 고칠 수 있다. 칸을 비우면 본문의 첫 글자 문단(인용·목록 안 포함, 그림·코드 제외)을 150자로 줄여 채우고, 글자 문단이 없으면 제목을 쓴다.
- 출간 화면을 열지 않고 저장(임시저장·자동 저장)하면 글에 적힌 요약을 지킨다. 그 요약이 예전 본문 첫 문단에서 자동으로 만든 것이면 지금 본문으로 다시 만든다. 출간 화면의 요약 칸도 자동으로 만든 요약은 비워 두고 직접 쓴 요약만 보여 준다.
- 글 화면은 본문이 요약과 같은 문단으로 시작하면 그 문단을 글 머리로 옮기고, 요약이 제목이거나 본문에 이미 있으면 글 머리를 비워 같은 글이 두 번 보이지 않게 한다. 사이트 빌드와 작성 화면이 같은 규칙(`src/article-summary.mjs`)을 쓴다.
- 서식 단추는 고른 줄·글자에 문법을 넣고 다시 누르면 뺀다. Ctrl/Cmd+B·I·K는 굵게·기울임·링크다.
- 작성·출간 화면은 브라우저 기록에 한 칸씩 쌓여 뒤로 가기로 하나씩 닫힌다. 저장하지 않은 내용이 있으면 확인 창을 띄운다.
- 저장은 글 머리의 고친 항목만 바꾸고 다른 항목과 따옴표 모양은 유지한다(`src/admin-model.mjs`).
- 다른 곳에서 먼저 바뀐 글은 덮어쓰지 않고 새로고침을 안내한다. 삭제는 확인 창을 거친다.

## 배포

글 원본은 비공개 Vault 저장소에 있다. 홈페이지 저장소는 공개이므로 임시 글은 올리지 않고, 출간한 공개 글만 Vault 동기화와 같은 경로(`publish/` → `content/blog/`, `assets/` → `content/assets/`)로 승인 사본에 함께 커밋한다. 배포는 이 사본으로 빌드한다. 저장소 비밀 값 `VAULT_TOKEN`이 있으면 배포가 Vault의 `publish`·`assets`를 직접 읽어 공개 글을 싣는다. 임시 글의 형식 오류는 공개 글 배포를 막지 않는다.

## 로그인

로그인 서버 주소(`authUrl`)가 없으면 GitHub 토큰으로 로그인한다.

1. "토큰 만들기"가 이름·설명·권한(Contents 쓰기, Actions 쓰기)을 미리 채운 GitHub 토큰 화면을 새 창으로 연다. 저장소는 Vault와 홈페이지 둘을 고른다.
2. 만든 토큰을 붙여 넣으면 GitHub에 토큰 주인이 글 저장소 주인인지, 글 저장소와 사이트 저장소(`deploy`의 저장소)에 모두 쓸 수 있는지 확인한 뒤 이 브라우저의 `localStorage`에 둔다. 빠진 저장소는 이름으로 알린다.
3. 이미 로그인한 토큰에 사이트 저장소 쓰기 권한이 없으면 작성 기능을 불러올 때 알린다. 출간 중 사이트 커밋이 권한 때문에 막히면 글은 Vault에 저장됐다고 알리고 다시 로그인한 뒤 수정하기로 반영하게 한다.

`authUrl`이 있으면 GitHub OAuth로 로그인한다.

1. "GitHub로 로그인"이 로그인 서버의 `/auth?origin=<사이트 주소>`를 새 창으로 연다.
2. 로그인 서버(`workers/admin-auth`)는 허용한 사이트 주소(`ADMIN_ORIGINS`)인지 확인하고 일회용 상태 값을 쿠키에 둔 채 GitHub 승인 화면으로 보낸다.
3. 돌아온 코드를 비밀 값(`GITHUB_CLIENT_SECRET`)으로 토큰으로 바꾸고, 토큰 주인이 허용한 계정(`ALLOWED_LOGINS`)이면 연 창에만 토큰을 보낸다.
4. 사이트는 로그인 서버 출처의 메시지만 받고 토큰을 `localStorage`에 둔다.

어느 쪽이든 로그아웃은 `/admin/`에서 하며 토큰을 지운다.

## 준비

- 토큰 로그인은 준비가 없다. `/admin/`에서 토큰을 만들어 붙여 넣는다.
- OAuth 로그인을 쓰려면 `workers/admin-auth`를 `npx wrangler deploy`로 배포하고, GitHub OAuth 앱(콜백 `https://<로그인 서버 주소>/callback`)을 만든 뒤 `wrangler secret put`으로 `GITHUB_CLIENT_ID`·`GITHUB_CLIENT_SECRET`을 넣고 `config/admin.json`의 `authUrl`에 주소를 넣는다.
