# 개인 사이트 발행

## 계약

위키와 블로그는 고정 ID와 단일 본문을 공유한다. 유형은 wiki 또는 blog이며 위키 탐색에서 블로그를 참조해도 유형과 댓글 ID는 바뀌지 않는다. 공개 입력과 원문 출처의 SHA-256을 발행 목록에 기록한다. 개인 정본에 직접 쓰지 않는다.

블로그의 최초 발행일은 수정일과 구분한다. 초안과 미래 발행 글은 HTML, 검색 색인, RSS, 사이트맵에서 제외한다. 블로그 댓글 비활성화, 중복 ID, 중복 slug, 존재하지 않는 태그와 잘못된 날짜는 빌드 오류다.

문서의 선택 필드 `parent`는 부모 문서의 slug이며 생략하거나 null로 둘 수 있다. 공개 위키 문서 전체에서 탐색 구조를 한 번 만들고 다른 category의 부모도 연결한다. 자기 참조나 부모 순환은 결과를 쓰기 전에 문서 slug와 함께 빌드 오류로 알린다. 부모가 미발행이거나 블로그이면 해당 문서를 최상위에 둔다. 원문 부모 관계를 고치거나 비공개 부모를 발행하지 않는다.

각 category의 탐색에는 해당 분류의 문서를 포함한 루트 트리를 중복 없이 넣는다. 원래 부모·자식 관계를 깊이 제한 없이 보존하므로 다른 category의 부모와 자식도 같은 트리에 남는다. 블로그는 계층에 섞지 않는다. 구조 검증은 입력 깊이에 따른 재귀 호출 없이 수행하며 상세 화면은 이미 검증된 주제 목록을 공유한다.

문서 계층과 본문 목차는 본문 밖의 탐색 열을 사용한다. 정적 HTML에서는 열려 있어 스크립트 없이도 링크로 이동할 수 있다. 스크립트는 좁은 화면에서 왼쪽 문서 탐색만 접는다. 본문 목차는 모든 폭에서 목록을 그대로 보이며 넓은 화면에서는 오른쪽 고정 열로 표시한다. 본문의 최대 읽기 폭은 680px다.

코드 블록은 공통 테마의 불투명한 옅은 회색 면으로 본문과 구분한다. 언어·복사 버튼 행과 코드 본문에 같은 배경을 쓰며 Plain text와 구문 강조 코드 모두 적용한다. 인라인 코드·표·인용문은 기존 면을 유지한다.

블로그 상세는 위키와 달리 Things 단일 글 구조를 쓴다. 검색과 제목 아이콘 없이 날짜, 제목, 소개, 대표 이미지, 본문 순서이며 피드의 `app-blog-post` 구조와 스타일을 공유한다. 댓글은 본문 뒤에 둔다. 개인 블로그의 카드와 본문에는 작성자 이름·아바타를 표시하지 않는다. 댓글 작성자 표시는 유지한다. 태그는 문서와 블로그 모두 도입문 다음, 본문 앞에 같은 TagList로 표시한다. 태그가 없는 글은 태그 영역을 생성하지 않는다. 날짜 옆의 예시 글 표시는 제거하며 example 값은 발행 제어에만 사용한다. 빈 꼬리말도 생성하지 않아 본문에서 댓글로 이어진다. 글 작성과 지원 문법은 [Markdown 글 작성](markdown.md)에 정리한다.

## 화면

홈은 `content/home.md`의 `sections` 순서대로 그린다([홈 원고 가이드](home-content.md)). 섹션의 아이콘·제목·설명·링크는 설정을 따른다. 기술 아이콘과 동료평가의 자동 흐름은 사용자가 요청한 확장이다. 2026-10-10 Things 공식 홈에서 Next Posts와 Previous Posts로 후기 묶음이 수동 전환되는 것을 확인했으며 자동 흐름과 구분한다.

기술과 동료평가는 공통 `FlowRail` 안의 트랙을 Web Animations의 선형 `transform`으로 이동한다. 가장 긴 행이 기존 rail 시간 토큰의 두 배 주기로 한 바퀴를 돌고 나머지 행도 같은 픽셀 속도를 사용한다. 매 프레임 `scrollLeft`를 쓰지 않아 저속 이동의 정수 픽셀 반올림을 피한다. 원본 뒤에 화면을 채우는 만큼 같은 묶음을 복제하고 원본 너비와 간격만큼 이동해 반복 경계를 잇는다. 복제 링크는 마우스로 열 수 있지만 `aria-hidden`과 `tabindex=-1`로 중복 접근성 탐색에서 제외한다.

키보드 초점·가로 휠·터치 조작·움직임 줄이기 상태에서는 애니메이션을 현재 위치의 네이티브 스크롤로 넘긴다. 마우스를 올리거나 떼는 것만으로는 흐름을 멈추거나 다시 시작하지 않는다. 가로 휠 조작 뒤 마우스가 나가거나 키보드 초점이 벗어나면 그 위치에서 이어지며 터치로 직접 넘긴 행은 해당 영역이 화면 밖으로 나갔다 다시 들어올 때 재개한다. 화면 밖·백그라운드·페이지 캐시 대기 중에는 시간을 진행시키지 않는다. 화면 크기가 바뀌면 진행 비율을 유지해 행 너비와 복제 수를 다시 계산한다.

인터뷰는 `content/interviews.md`의 `items`에 id·summary와 선택 `profile`(이미지·제목·부제목 세 자리)을 적는다. 선택 `url`(HTTPS)은 카드 전체에 연결되며 요약 안의 링크는 자기 주소로 열린다. `example: true`인 카드는 미리보기에서만 표시한다. 공개 원고에는 예시 카드 다섯 장이 있으며, Git에서 제외되는 `content/interviews.local.md`를 연결하면 미리보기에서만 검토 카드로 대체한다. 표시할 카드가 없으면 섹션을 제외한다. 흐름 스크립트는 기술이나 인터뷰 섹션이 켜져 있을 때만 포함한다. 홈의 프로젝트·기술·인터뷰·연락은 공통 머리 구조(아이콘, 제목, 설명, 링크 행)를 쓴다. 연락 구간은 실제 이메일 주소의 메일 링크만 제공한다. 한 줄 푸터는 구분선 아래 여백을 줄인 의도된 예외다.

공통 헤더의 보이는 제목은 `config/site.json`의 `name`이며 홈 링크의 접근성 이름도 같은 이름을 사용한다. 아이콘은 공통 `ControlIcon`을 헤더의 아이콘 슬롯에 전달한다.

공통 푸터의 소셜 링크는 GitHub, LinkedIn, RSS 순서다. LinkedIn은 `config/site.json`의 `linkedin` 주소를 사용하며 값이 없으면 링크를 만들지 않는다. 홈의 인터뷰 머리에 있는 LinkedIn도 사용자가 지정한 같은 프로필 주소로 연결한다.

노트 입구는 `app-body`의 680px 읽기 열을 사용한다. 검색창·Blog·분야 목록의 정렬선을 맞춘다. 블로그 미리보기는 두 열·최대 네 편이고, 다섯 편부터 전체 보기를 제공한다. `BlogCard`는 5:2 썸네일, 한 줄 말줄임 제목, 최대 두 줄 설명을 표시한다. 입구 순서는 Blog → 프로젝트 → CS → Tech다. 프로젝트는 `config/site.json`의 `notes.projects: false`로 비활성화하며 빈 제목이나 여백을 표시하지 않는다. `content/tech.md`의 `topics`의 `group`이 표시할 영역을 결정한다. Tech는 공식 로고·제목만 네 열·최대 여덟 항목으로 표시한다. CS는 아이콘·제목·두 줄 설명을 세 열·최대 여섯 항목으로 표시한다. 입구의 두 영역은 Blog와 같은 680px 폭을 유지한다. Projects는 영역을 지정하지 않아 표시하지 않는다. 각 한도를 넘으면 전체 보기에서 앞의 항목을 포함한 모든 주제를 보여 준다. Blog·CS·Tech 전체 목록은 모두 헤더와 같은 최대 900px 폭을 사용하고 각각 3열·4열·5열로 표시한다. 검색창 뒤의 공통 목록 머리에는 제목과 돌아가기가 순서대로 놓이며 건수·정렬 설명은 표시하지 않는다. 제목과 돌아가기 사이 16px, 첫 카드까지 24px 간격을 둔다. CS·Tech 카드 아이콘은 32px 영역과 제목 앞 8px 간격으로 통일한다. Wiki 중간 제목은 생략한다. 두 목록은 `CardGroup`의 공통 간격과 반응형 규칙을 사용한다.

썸네일 카드의 전체 제목은 링크의 접근성 이름과 글 상세에 유지한다. 전체 목록은 h1 아래 카드 h2, 최신 글 미리보기는 h2 아래 카드 h3을 사용한다. 카드 설명 아래에는 태그를 한 줄로 표시하고 넘치는 태그는 숨긴 뒤 말줄임표를 표시한다. 그 아래에는 발행일과 댓글 수를 작은 회색 글씨로 표시하며 작성자 이름과 아바타는 생략한다. 날짜 옆 예시 글 표시도 생략하고 내부 example 값으로 운영 발행에서 제외한다. 썸네일·제목·설명·정보 행·여백은 글을 열고 태그는 독립 링크로 동작한다. 키보드로 글 링크와 각 태그에 접근할 수 있다. 본문의 태그도 같은 독립 링크다. 날짜는 한국어로 표시하되 time 요소에는 원래 날짜를 보존한다. `thumbnail.alt`는 대체 설명이며 선택 `position: { x: 50, y: 50 }`은 자르기 위치의 가로·세로 백분율이다. 각 값은 0~100의 유한한 숫자이며 생략하면 가운데에 맞춘다. 이미지별 좌표와 원본 크기는 콘텐츠 데이터다. 알려진 원본 크기는 `config/image-sizes.json`에 기록하고 표지와 문서 이미지가 같은 목록을 읽는다. 표지의 항목 키는 `thumbnail.src` 전체 값이다. 크기가 없는 표지는 임의의 width·height를 출력하지 않는다. 피드와 상세는 원본 비율을 유지하며 카드의 자르기 비율·표면·곡률·여백은 공통 테마에서 읽는다.

위키 문서 상세는 제목, 소개, 날짜·태그, 목차, 본문, 관련 문서를 분리한다. 2026-10-08 사용자 요청에 따라 상세·관련 글·검색·태그에서 Wiki·Blog 유형 표시와 유형 탭을 제거한다. 상단 메뉴는 탐색 목적지로 유지하고 데이터의 유형·발행·댓글 규칙은 유지한다. Things Support에서 tags 검색 후 결과와 Using Tags 상세로 이동해 유형 표식 없는 제목·설명 위계를 대조했다. 예시 글의 안내는 유지한다. 제목을 본문 `.app-prose` 안에 넣지 않아 본문 h1의 여백이 제목에 겹치지 않게 한다. 제목은 36px·줄 높이 1.2, 소개는 22.5px·1.25, 본문은 18px·1.4다. 본문 h2는 27px·1.25와 아래 구분선을 사용한다. 값과 관련 카드의 상태는 [Things Getting Things](https://culturedcode.com/things/support/articles/2803552/)에서 직접 대조한다.

문서는 현재 글의 H2·H3 링크를 오른쪽 탐색 열에 표시하며 별도 목차 제목은 생략한다. JavaScript 없이도 해당 절의 고정 앵커로 이동한다.

작업 목록의 체크박스는 항목 본문을 label로 연결하며 읽기 전용을 유지한다. 하위 목록은 상위 항목의 이름에 포함하지 않고 링크·강조·코드의 서식을 보존한다. 완료·취소 표기는 [Things Markdown Guide](https://culturedcode.com/things/support/articles/4651820/)의 의미를 따른다. 태그 링크 묶음은 이름이 있는 group 역할로 전달하며 펼치기는 기본 details 요소를 사용한다.

발행 렌더러는 첫 최상위 문단이 소개 전체와 같을 때만 그 문단을 소개로 옮긴다. 링크·강조·코드·각주를 유지하며 원본 Markdown은 바꾸지 않는다. 일부 문장만 같거나 인용문·목록·이미지로 시작하면 본문을 유지한다. 상세와 본문 피드는 같은 소개 HTML을 사용하고 내부 링크 변환은 소개와 본문 양쪽에 적용한다.

글 하단에 자동으로 추천 목록을 붙이지 않는다. 작성자가 고른 이어서 읽을 글은 공통 `Card`의 `related` 변형으로 조립하며 작은 아이콘·한 줄 제목·갈매기표를 표시한다. 설명은 표시하지 않고 긴 제목은 말줄임한다. 블로그 자동 추천 정책은 [관련 글 선정 기준](https://github.com/woonyong-choi/homepage/issues/117)에서 추적한다.

검색 결과는 태그 줄과 여백까지 한 행으로 강조하며 태그 외 영역은 글을 연다. 태그 링크는 그 위에서 독립적으로 동작하고 글 링크의 키보드 초점은 행 전체에 표시한다.

검색의 화면 코드와 Worker는 esbuild로 각각 묶어 두 요청으로 불러온다. 산출물 내용 해시를 두 진입점에 함께 적용한다. 검색 스크립트는 본문 뒤에서 async 모듈로 실행해 스타일시트 완료를 기다리지 않으며, 스타일 토큰을 읽는 문서·영상 등은 기존 모듈 초기화 순서를 유지한다. 원본 소스의 모듈 구분은 유지하고 중간 검색 모듈은 배포하지 않는다.

검색은 한글 조합 완료 후 실행한다. 검색어의 각 낱말과 선택 태그는 AND로 결합한다. 검색 결과의 태그를 누르면 현재 검색어와 선택 태그를 보존한 채 중복 없이 추가하고 첫 페이지로 이동한다. 이미 선택한 태그를 다시 눌러도 조건은 늘어나지 않는다. 검색과 태그 화면은 문서 유형을 구분하지 않고 모든 글을 함께 보여준다. 유형별 집계는 내부 모델에만 남긴다. 검색 URL은 검색어, 태그, 페이지를 복원한다. 이전 type 파라미터는 무시하며 첫 페이지로 돌아가고 주소에서도 제거한다. 새 태그 링크와 검색 URL에는 유형을 넣지 않는다.

검색 결과 화면에서 검색어 지우기는 검색어만 비우고 태그가 남으면 첫 페이지의 결과를 같은 화면에 표시한다. 태그 해제도 남은 검색어와 태그를 유지한다. 마지막 조건을 지우거나 조건 초기화를 누르면 Search 입구의 주제 목록으로 돌아간다. 검색어·태그 없이 검색 결과 주소에 직접 들어오면 전체 색인을 조회하지 않고 입구로 연결하며, 빈 검색 주소를 방문 기록에 남기지 않는다. 쪽 번호나 이전 type 파라미터만 있는 주소도 같다. Search 입구에서 입력을 지우면 추천만 닫고 현재 화면을 유지한다. 추천을 닫으면 접근성 상태는 본문 결과 안내로 돌아가며, 색인 로딩 실패는 오류와 재시도 안내를 알린다. 추천의 재시도 항목도 방향키와 Enter로 선택할 수 있다.

2026-10-08 Things 공식 Support와 문서 내부 검색의 입력·Enter·해제·외부 클릭을 직접 대조했다. 개인 사이트도 입력창 안에 지우기를 두고, 입력 바로 아래의 정적 흐름에 결과를 펼쳐 기존 본문을 유지한다. Enter는 선택한 항목을 실행하거나 현재 결과를 확인하며 별도 화면으로 강제 이동하지 않는다. 전체 결과로 이동할 때는 명시적인 전체 검색 결과 링크를 사용한다. 전체 결과 화면에서는 입력에 따라 현재 결과와 URL을 갱신한다. 추천과 전체 결과는 같은 17px 제목·설명, 22.1px 줄 높이, 12px 패널 곡률과 일치어 강조를 사용한다. 연관 검색어·태그·페이지네이션은 원본에 없는 승인 확장으로 구분한다.

검색 화면을 떠날 때 위치를 해당 history 항목에 기록한다. 브라우저의 뒤로가기 캐시가 살아 있으면 기존 결과 DOM을 유지하고, 다시 생성해야 하면 결과를 그린 뒤 기록한 위치로 돌아간다. 결과를 다시 그리면서 스크롤 기준 행이 사라지는 일을 피한다.

태그 정적 HTML은 조건별 검색 결과를 비워 둔다. 모든 글은 별도의 `이 태그의 모든 글 보기` 접기 영역에 두고, 검색어를 적용하지 않은 전체 목록임을 표시한다. 스크립트 미사용과 색인 오류에서도 이 정적 링크로 글을 읽을 수 있다. 검색을 시작하거나 한글을 조합하는 동안에는 이전 결과·페이지 링크를 지우고 대기 상태를 표시한다. 현재 요청의 결과만 표시한 뒤 대기를 해제한다. 전체 목록을 읽거나 초점을 둔 경우에는 결과가 도착해도 그 영역을 숨기지 않는다. 뒤로가기 캐시에서 돌아왔을 때 결과가 완성돼 있으면 기존 화면과 위치를 유지하고, 로딩 중이었다면 현재 URL의 검색을 다시 실행한다.

## 입력

`content/docs/`와 `content/blog/`는 승인된 문서 입력이다. `config/approved-content.json`은 두 폴더의 승인 해시를, `config/publication-manifest.json`은 가져온 위키의 식별자와 원문 출처를 기록한다. 공개 투영을 가져올 때 원래 사이트의 공개 입력 검사를 먼저 실행하고 `node src/import-publication.mjs <공개 사이트 루트> <비공개 자료 루트>`를 사용한다. 이미 발행한 본문을 임의로 블로그로 재분류하거나 발행일을 만들어 넣지 않는다.

`config/site.json`은 사이트 이름·소개문·GitHub·`/projects/` 목록과 댓글 설정을 관리한다. 홈 화면의 구간 순서·소개·영상·프로젝트·연락은 `content/home.md`, 기술 링크와 분야는 `content/tech.md`, 인터뷰는 `content/interviews.md`가 정본이고, `projects`는 홈과 무관한 `/projects/` 페이지 전용이다. `repository`의 owner/name 식별자는 댓글과 토론 링크에 사용하며 잘못된 경로는 빌드 오류다. 댓글 저장소 ID와 분류 ID는 해당 저장소의 실제 giscus 설정과 함께 갱신해야 한다. 토론 검색에는 설정된 분류 이름을 사용한다. 없는 개인 영상과 추천은 표시하지 않는다. `content/tech.md`의 `topics`은 내부 분류와 주제 입구를 정의한다. 공통 태그의 이름·별칭은 `config/tags.json`에서 별도로 정의한다.

`documents/examples/`의 기술 글과 문법 가이드는 문제·대안·구현·검증·한계 순서의 미리보기 자료다. 예시 표시를 유지하고 RSS와 운영 빌드에서는 제외한다. 입력이 다른 폴더로 이동해도 `example: true`인 문서는 운영 HTML·검색·사이트맵에서 제외한다. 주제 개요가 미발행 상태여도 같은 주제의 공개 글이 있으면 그 글을 대표 링크로 사용한다.

## 실행과 댓글

`npm run build:site`는 검색 제외 미리보기를 만든다. `SITE_ORIGIN=<확정된 HTTPS 주소> npm run build:site -- --production`은 실제 공개 글만 발행한다. 확인되지 않은 운영 주소를 기본값으로 넣지 않는다. 현재 저장소에 운영 배포 대상은 아직 지정되지 않았다.

운영 origin은 URL 파서로 검증한 정규화된 HTTPS 호스트다. 사용자명·비밀번호·경로·쿼리·해시·공백·불필요한 후행 슬래시가 있으면 출력 폴더를 변경하기 전에 실패한다. 포트가 필요한 경우 유효한 포트를 포함한 정규 origin을 사용한다. 로컬 미리보기만 HTTP origin을 허용한다. 2026-10-08 확인한 저장소의 GitHub Pages·환경·변수에는 운영 대상이 등록돼 있지 않았다.

탭 제목은 문서 제목과 개인 이름을 함께 표시하고 홈에서는 같은 이름을 반복하지 않는다. 설명은 본문의 공통 description을 사용한다. 기존 작은 문서 SVG를 파비콘으로 연결하고, 같은 도형에서 32·180·512픽셀 PNG를 빌드 시 생성한다. 각각 PNG 파비콘·홈 화면 아이콘·공통 공유 이미지이며 SVG 정본의 색과 도형을 바꾸지 않는다. PNG 이름에는 파일 내용 해시를 넣는다. SVG 변환기는 개발 의존성이며 브라우저에는 배포하지 않는다. 시스템 글꼴을 읽지 않아 같은 입력의 이미지가 재현된다. 원본 테마의 MIT 고지도 함께 발행한다.

origin이 지정되면 [Open Graph](https://ogp.me/)의 제목·설명·정식 주소·개인 사이트 이름·한국어 locale·공통 PNG 이미지와 대체 설명을 생성한다. 공유 이미지는 문서 썸네일을 가장하지 않는 사이트 공통 기록 아이콘이다. 글 상세는 내부 wiki/blog 유형과 관계없이 article, 목록은 website로 기록한다. 실제로 등록된 발행일·수정일·태그만 포함한다. Twitter summary 메타데이터도 같은 값에서 만든다. origin 없는 미리보기에는 정식 주소와 공유 URL을 만들어 넣지 않으며 검색 제외를 유지한다. 외부 공유 서비스의 캐시와 실제 공개 응답은 운영 배포 뒤 별도로 검증한다.

본문 탐색과 블로그 페이지네이션은 정적 HTML이다. 본문 탭·갤러리·복사·문서 목록·영상 등 상호작용은 실제 페이지가 사용하는 공통 런타임만 포함한다. 클라이언트 모듈은 묶음 내용 해시를 URL에 포함해 이전 import가 캐시에 남는 것을 방지한다. 코드 블록과 ThinkFlow 원문 복사는 공통 조작과 피드백을 사용한다. 스크립트가 연결된 경우에만 버튼을 표시하고, 복사 중에는 초점을 유지하면서 중복 요청을 막는다. 완료·실패는 각 코드의 상태 영역으로 알리며 버튼의 짧은 표시와 접근성 이름을 함께 갱신한다. 실패해도 원문 선택과 재시도는 가능하다.

각 HTML에서 검색·문서 조작·댓글의 실제 요소를 확인해 해당 모듈만 연결한다. 프로젝트 목록은 클라이언트 모듈 없이 표시한다. 홈은 기술 또는 인터뷰 흐름에 공통 흐름 모듈을 연결하고, 영상이 있을 때만 공통 영상 모듈을 추가한다. 검색 모듈이 문서 조작과 댓글 모듈을 함께 불러오지 않는다.

발행 자산은 HTML의 이미지·링크·poster, 검색 색인의 아이콘, CSS의 상대 URL과 import를 따라 수집한다. iframe이 직접 읽는 giscus CSS도 발행한다. 경로는 theme·assets·media 안으로 제한하며 의존 파일 누락과 경로 이탈은 빌드 오류다. 테마의 제작용 JSON·렌더러·소스 CSS는 사용하지 않으므로 복사하지 않는다. 사용한 글꼴·기술 로고·프로젝트 미디어의 고지는 배포 의존 파일로 함께 복사한다. 참조되지 않은 자산의 고지는 제외하고 필요한 고지 파일이 없으면 빌드 오류다. 테마 원본의 파일 해시 검사는 복사 전에 유지한다. 아이콘 파일은 실제 HTML과 검색 색인에서 참조한 것만 발행한다. 토큰 파일과 giscus CSS는 그대로 유지한다. 공통 styles.css는 정본 해시를 먼저 검증한 뒤 발행 HTML과 묶인 브라우저 스크립트에서 사용한 선택자만 publication.css로 생성한다. 선택자의 선언 값은 바꾸지 않는다. is-·has- 상태 클래스, CSS에 등장하는 속성의 동적 값, 글꼴 선언, keyframes와 변수는 보존한다. 산출물의 SHA-256을 스타일 링크의 버전으로 사용하고 빌드 보고서에 원본·결과 크기와 제거한 선택자 수를 기록한다.

검색 색인은 사용 시점에 Web Worker에서 읽고 파싱·정규화한다. 같은 공개 데이터에서 JSON과 gzip 파일을 함께 생성하고, Worker가 gzip을 우선 읽는다. 압축 해제 API가 없으면 JSON을 바로 읽고 압축 파일의 전송·해제·형식 검사에 실패하면 JSON으로 복구한다. 두 요청은 하나의 15초 제한을 공유한다. 호스트가 이미 압축을 해제한 응답은 바이트 머리로 구분해 이중 해제를 피한다. 실패한 요청은 캐시하지 않으며 재시도할 수 있다. 호스트의 HTTP 압축 설정과 관계없이 두 파일을 함께 배포해야 한다. 화면 스레드에는 표시할 행과 유형별 개수만 전달한다. 페이지를 옮겨도 같은 색인을 다시 받지 않도록 Worker에서 `publication-search-v1` Cache API 저장소를 사용한다. 매번 작은 `search-version.json`을 HTTP 캐시 없이 확인하고, 공개 색인 전체 바이트의 SHA-256과 같은 버전만 읽는다. 본문·태그·공개 문서 집합이 바뀌면 버전도 바뀐다. 캐시와 네트워크 응답 모두 해시와 형식을 검사한다. 압축을 푼 색인을 저장하며 다른 버전은 자체 저장소에서만 제거한다. 저장소 없음·열기 거부·쓰기 실패·손상은 직접 읽기로 복구한다. 버전 파일이 없으면 기존 색인을 직접 읽고 저장하지 않는다. 배포 도중 버전과 색인 파일이 어긋나면 오류로 처리하며 재시도 때 버전부터 다시 확인한다. 저장소를 영구 보존하는 권한은 요청하지 않는다. 검색어를 바꾼 뒤 도착한 이전 추천은 버린다. 본문에서만 일치한 결과는 일치 지점 주변을 발췌하고, 로딩 실패는 빈 결과와 구분해 재시도를 제공한다. Escape는 입력값을 유지하고 추천만 닫는다.

댓글은 공개 homepage 저장소의 Comments 분류에 `specific`·strict 방식으로 문서 ID를 연결한다. 한국어·오래된 댓글 순서이며 반응 모음은 끈다. 테마는 같은 공개 사이트에 발행한 CSS의 해시 주소를 사용한다([댓글 테마 배포](#댓글-테마-배포)). 부모의 스타일이 iframe에 상속된다고 가정하지 않는다. 상세에서는 전체 댓글과 상단 작성란을 바로 보여 준다. 피드는 각 글 아래에 실제 댓글을 240px 높이로 보여 주며 하단으로 흐려진다. 영역 전체가 기본 버튼이고 선택하면 그 자리에서 제한을 해제하며 해당 iframe으로 초점을 옮긴다. 접힌 iframe은 inert·aria-hidden으로 조작 대상에서 제외한다. 피드의 작성란은 댓글 아래에 있어 미리보기에서 댓글이 먼저 보인다.

피드는 [Things 공식 블로그](https://culturedcode.com/things/blog/)에서 관측한 전체 너비 구획과 4px 구분선을 사용한다. 본문 680px·확장 이미지 900px과 제목·본문 위계는 유지하고 날짜는 한국어로 표시한다. 글 상세·댓글 보기의 중복 링크는 제거하고 제목의 상세 링크를 유지한다. 무한 이어 읽기는 소비자 확장으로 유지하며 다음 정적 페이지의 구획 전체를 순서대로 추가한다. 추가된 글의 댓글도 `content-added`에서 초기화하되 이미 연결된 iframe과 펼침 상태는 유지한다.

단일 컨테이너를 찾는 외부 client.js를 여러 번 주입하지 않고 [giscus 공식 클라이언트](https://github.com/giscus/giscus/blob/main/client.ts)의 widget URL·세션·메시지 형식에 맞춰 iframe을 글별로 연결한다. 토론 고정 ID, 고유 앵커, 글 상세 backlink를 전달하고 message의 origin과 source를 모두 확인한다. 높이·오류·토론 URL은 해당 iframe에만 적용한다. 로그인 반환값은 주소에서 제거하고 같은 출처 저장소에 유지하며 저장소가 차단되면 현재 화면에서만 유지한다. 로그아웃·세션 만료는 로드된 댓글 전체에 반영한다. 처음 페이지에 있는 댓글은 스크롤 전에 모두 연결하고, 다음 글은 한 화면 앞에서 미리 가져와 추가된 댓글도 즉시 연결한다. 시간 초과·실패 시 재시도와 GitHub 링크를 제공한다. 처음 댓글이 없는 상태는 오류로 취급하지 않는다.

giscus 설치에 homepage 저장소를 연결했고 실제 첫 댓글·새로고침·답글 저장을 확인했다. 검증 토론은 [댓글 연결 검증](https://github.com/woonyong-choi/homepage/discussions/29)에 있다. 위키는 `comments: true`인 글만 댓글 영역을 연다. 수정 제안 링크는 표시하지 않는다.

댓글의 기본 GitHub 탭 바와 이중 테두리는 제거하고 기존 입력·버튼 역할을 적용한다. 댓글·답글·미리보기 본문은 모두 18px, 작성자·날짜·조작은 15px, 입력창의 곡률은 12px다. 댓글의 외곽 테두리·회색 패널은 없고 답글은 들여쓰기와 얇은 구분선으로 구별한다. 입력 초점은 textarea 안쪽에 한 번만 표시해 iframe 경계에서 잘리지 않게 한다. 답글 연결선은 아바타 중심 아래에 두고 본문과 분리한다. 고정폭 글꼴 버튼과 Markdown 안내는 숨기고, GitHub 직접 열기는 로딩 오류 또는 JavaScript 미사용 시에만 표시한다. 테마 변수를 치환하는 것만으로 적용 여부를 판정하지 않고 실제 iframe의 계산 스타일을 확인한다. iframe 높이 알림은 기존 댓글 수를 초기화하지 않는다.

2026-10-08 작업본에서 공개 위키 220개와 예시 5개의 320px 본문을 검사했다. 제목·문단·코드가 페이지 폭을 넘는 항목은 없고 긴 표는 별도 가로 스크롤 영역에 들어간다. 주요 화면 7개를 다섯 폭에서 대조한 35개 조합에서도 페이지 전체 가로 넘침은 없었다. 이 기록은 운영 배포·사용자 최종 디자인 승인과 구분한다.

발행 사이트는 공통 토큰·구성 요소·CSS·동작을 조립한다. 빌드가 사용 선택자와 변수만 남기며 정본 사본을 수정하지 않는다. 도표도 빌드 때 생성하고 브라우저에서는 재생만 한다.

CSS 상속 변경 전후에 홈·위키·프로젝트·블로그·검색·문서의 45개 대표 화면에서 8415개 요소의 계산 스타일을 대조했다. 비교한 속성의 차이는 0개다. 실제 225문서를 1440·1024·768·390·320px에서 열어 가로 넘침, 본문 잘림, 중복 페이지 제목과 로드 완료 이미지의 실패를 검사했다. 이 기계 검사는 모든 문서의 육안 디자인 승인이나 지연 이미지 전체의 로딩 검사를 대신하지 않는다.

## 발행 자산 검증

2026-10-08 공개 문서 220개의 운영 빌드에서 사용하지 않는 선택자 561개와 자산 23개를 제외했다. 자산 수집 결과는 69개·3198262바이트에서 46개·2749127바이트로 줄었다. 스타일은 115524바이트에서 38287바이트로 줄었다. HTML·검색 색인 등 나머지 출력까지 포함한 비 HTML 파일은 82개에서 59개가 되었다. 이 수치는 파일 크기이며 네트워크 응답 시간 측정과 구분한다.

운영 250페이지의 78594개 요소를 같은 DOM에서 정본 스타일과 교체 대조했다. 배치·글꼴·색·배경·테두리·곡률·여백·간격·열·최대 폭·그림자·정렬·넘침의 비교 속성 차이는 0개였다. 미리보기 여덟 경로를 다섯 폭에서 검사했고 가로 넘침은 없었다. 영상 재생, 인터뷰 이동, 모바일 문서 목록 펼치기, 검색 키보드 선택도 대조했다. 로딩 중 관측한 자동 여백 차이는 같은 DOM의 레이아웃 완료 후 재검사했다. 이 검사는 전체 상호작용·픽셀 동일성·사용자 최종 디자인 승인을 대신하지 않는다.

PurgeCSS는 빌드에서만 사용한다. 버전과 전이 의존성의 고정 값은 `package.json`과 `package-lock.json`이 정한다. 의존성을 바꿀 때는 현재 `npm audit` 결과와 실제 발행 스타일의 출력 차이를 함께 검사한다.

아이콘 이름·별칭·분류·문서 표식·브랜드와 고지는 테마의 `assets/icons/catalog.json`에서 읽는다. SVG는 `assets/icons/<분류>/<이름>.svg` 한 곳에 있고 상세 변형은 `-detail.svg`로 구분한다. 홈페이지는 공통 `iconFile`·`readIcon`·`renderSvgIcon`을 통해 경로와 인라인 도형을 조립한다. 검색·영상 조작은 `ControlIcon`을 쓰고 재생 상태의 SVG 교체도 공통 영상 런타임이 맡는다. 별도 조작 이미지를 발행하지 않는다. 인라인 SVG와 그 원본에서 파생한 사이트 아이콘의 고지는 카탈로그가 지정한 라이브러리·브랜드 고지의 합집합을 한 번씩 발행한다. 글꼴·회사 로고·미디어 고지도 해당 자산과 함께 보존한다.

## 랜딩의 위계와 폭

소개와 영상은 옅은 바탕, 기술·인터뷰·연락은 흰 바탕으로 구분한다. 홈 헤더도 원본처럼 공통 구분선을 표시한다. 제목은 기존 단계로 계산한 63px이며 모바일은 36px다. 이 한글 제목 크기는 원본의 이미지 로고를 대신하는 확장으로 원본 실측값과 구분한다. 영상은 헤더 콘텐츠와 같은 최대 900px로 보여 주며 재생 버튼은 데스크톱 88px·모바일 44px다. 영상 설명은 중앙에 모으고 메일은 하나의 행동 링크로 제공한다.

기술과 인터뷰 흐름도 공통 900px 콘텐츠 안에 둔다. 영상·흐름·조작 영역은 헤더 콘텐츠와 같은 중앙 정렬선을 따른다. 전체 배경만 화면을 채운다. 인터뷰 폭은 440px 이내이며 좁은 화면에서는 화면 양옆 여백을 남긴다. 별도 정지 버튼은 표시하지 않는다. 키보드 초점과 터치·가로 스크롤은 자동 이동을 멈추고 직접 탐색으로 전환한다. 전체 원본이 화면에 들어오는 넓이에서도 두 항목 이상이면 계속 흐른다. 화면을 채우는 데 필요한 복제 그룹 수를 계산하고 모두 접근성 탐색에서 제외한다. 단독 흐름의 한 항목은 흐르지 않는다. 인터뷰는 공개 항목을 순서대로 앞 절반(올림)과 나머지로 나눠 두 줄로 보이고, 한 장이면 한 줄이다. 두 줄일 때는 줄에 한 장뿐이어도 복제해 함께 흐르고, 두 줄 모두 카드 아래를 맞춘다. 두 줄은 서로 반대 방향이고 같은 픽셀 속도로 흐른다. 마우스를 올리거나 떼어도 이동은 유지하며 가리킨 항목만 1.05배 확대한다. 블로그 카드의 배경·테두리·그림자와 120ms 전환을 공유한다. 키보드 초점은 두 줄을 함께 멈춘다. 동작 줄이기에서는 자동 이동과 호버 확대를 생략한다. 모바일에서는 절 사이의 여백을 기존 48px 단계로 줄인다.

## 블로그 전체 목록

`/blog/all/`은 기존 900px 목록 열 안에 세 열 썸네일 카드를 배치한다. 최초 발행일 내림차순이며 같은 날짜는 ID 순서로 고정한다. 열두 편씩 만든 정적 페이지가 기본 자료다. `blog-list.js`는 목록 하단에 도달하면 다음 페이지의 카드를 읽어 붙인다. JavaScript가 없으면 원래 쪽 이동 링크를 사용하고 IntersectionObserver가 없으면 더 보기 링크로 불러온다. 한 번에 한 요청만 보내고 글 주소로 중복을 제거한다. 실패 후 자동 재요청은 멈추며 다시 불러오기로 재시도한다. 마지막 페이지 뒤에는 요청을 중단한다. 수동 추가 시 첫 새 글로 키보드 초점을 이동한다. 본문 이어 읽기는 기존 네 편씩 정적 페이지를 유지한다.

이 카드 구성과 추가 로딩은 Things 지원 페이지에 없는 사용자 요청 확장이다. 공식 지원 페이지에서 680px·두 열 336px·세 열 약 221px·간격 8px와 Show All의 별도 전체 목록 이동을 확인했다.

썸네일은 로컬 `/media/` 이미지 또는 자격 정보가 없는 HTTPS URL이다. 예시 글은 임시 [Picsum 이미지](https://picsum.photos/)를 seed별로 사용하며 운영 빌드에서는 예시 글과 함께 제외된다. 미등록 썸네일은 같은 비율의 빈 표면을 유지한다. 설명 줄 제한은 테마의 `component.card-summary-lines`를 사용한다. 분야의 표시 이름·설명·group은 사이트 소유 `content/tech.md`의 `topics`에 두고 공개 문서를 재수입할 때 보존한다. 원본 문서의 field는 입력 분류로 유지한다. 기존 분야 URL도 전체 목록으로 남기고 새 입구에서는 `/docs/topics/tech/`와 `/docs/topics/cs/`만 연결한다.

블로그 카드의 썸네일·제목·설명은 하나의 링크이며 추가 로딩의 중복 판별과 키보드 초점도 이 링크를 사용한다. 카드의 날짜·댓글 수와 빈 여백도 글을 열며 작성자 정보는 생략한다. 태그는 중첩하지 않은 독립 링크로 연결한다. 도움말 카드와 같은 호버·초점 배경, 외곽선, 그림자를 사용한다. 썸네일은 5:2로 줄여 336px 카드에서 이미지 높이가 약 188px에서 134px가 된다. 영상 및 본문 미디어의 비율은 바꾸지 않는다. 움직임 줄이기에서는 카드 위치를 움직이지 않는다.

## 목록 댓글 수

빌드에서 GitHub CLI의 인증을 사용해 설정한 저장소·Comments 분류의 토론과 댓글을 읽는다. 목록에 댓글 iframe을 여러 개 넣지 않는다. giscus의 strict 매핑과 같은 문서 ID의 SHA-1을 토론 본문에서 찾아 연결하므로 제목이나 URL 변경으로 연결이 바뀌지 않는다. 댓글 수는 최상위 댓글과 답글의 합이며 모든 토론·댓글 페이지를 읽는다. 토론이 없는 것이 확인된 경우만 0개로 표시한다. 인증 없음·네트워크 오류·불완전한 페이지·중복 매핑은 숫자 대신 댓글 보기 링크로 표시하며 본문 빌드를 막지 않는다. 빌드 보고서의 commentsStatus로 수집 결과를 구분한다.

숫자는 빌드 당시 값이며 다음 빌드 때 갱신된다. 브라우저로 인증 정보나 토론 본문을 전달하지 않는다. CI의 빌드 단계에는 저장소 내용과 공개 토론 읽기 권한만 부여한다. 참고: [giscus strict 매핑](https://github.com/giscus/giscus/blob/main/ADVANCED-USAGE.md#data-strict), [목록 댓글 수 안내](https://github.com/orgs/giscus/discussions/113).

발행 문서의 Markdown 구분선은 본문 전체 폭을 사용한다. 작업 목록은 Markdown에 적힌 완료·미완료·취소 상태를 표시하며 독자가 변경하지 않는다.

댓글 추천·반응 버튼은 공통 작은 버튼의 곡률·높이·간격과 회색 바탕을 사용한다. 선택과 호버는 파란색 역할로 구분한다. 반응의 의미·개수·서비스 권한은 바꾸지 않는다.

## 문서와 블로그 탐색

상단 메뉴 Search는 `docs/` 입구로 이동한다. 입구의 680px 폭과 Blog 2열·CS 3열·Tech 4열은 유지한다. 문서 상세는 `docs/<slug>/`, 블로그 상세는 `blog/<slug>/`, 검색 결과는 `search/`를 사용한다. 기존 `wiki/`·`wiki/<field>/`·`articles/<slug>/`는 새 주소로 연결하고 쿼리·해시를 보존한다. 이전 주소는 사이트맵에서 제외한다. 댓글은 URL과 별개인 고정 문서 ID를 계속 사용한다.

CS·Tech 상세의 왼쪽에는 [문서 계층 계약](#계약)에 따라 현재 category에 연결된 루트 트리를 표시한다. 다른 category의 문서도 부모·자식 관계에 따라 같은 트리에 남는다. Search는 상단 메뉴에서만 제공하고 문서 계층에 뒤로 링크를 섞지 않는다. 루트 문서 제목을 최상위 항목으로 사용해 같은 제목을 중복하지 않는다. 현재 문서의 조상만 자동으로 펼치며 다른 가지는 기본 접는다. 문서 계층에는 아이콘과 기본 삼각형을 표시하지 않는다. 하위 문서는 글자·들여쓰기·연결선·현재 항목 강조로 구분한다. 하위 항목이 있는 제목 전체를 누르면 열리고 다시 누르면 접힌다. 하위 항목이 없는 문서 제목은 해당 글로 이동한다. 파란 선택 배경은 클릭한 항목으로 이동하고, 선택한 가지의 조상 경로만 펼친다. 다른 가지와 그 하위의 펼침은 닫는다. 현재 본문 문서의 접근성 표시는 유지한다. 키보드 접기·펼치기를 유지한다. 1300px 이상에서는 왼쪽 탐색도 남는 열 전체를 사용하며 긴 이름은 잘리지 않고 줄바꿈한다. 기존 3단계 뒤 평탄화는 제거한다.

문서 하단은 왼쪽 탐색에 포함된 이전·다음 위키 문서로 이어진다. 순서는 사이드바의 부모 우선 순서이며 접힌 가지의 하위 문서도 포함한다. 첫 문서에는 이전 링크, 마지막 문서에는 다음 링크를 만들지 않는다. 문서가 하나면 영역을 생략한다. 공개 원문 링크 뒤, 댓글 앞에 공통 `PageLinks`의 텍스트 이동 링크를 배치한다. 각 링크는 이전·다음 방향과 전체 문서 제목을 표시하며 좁은 화면에서는 줄바꿈한다. 본문에 작성한 관련 글 카드는 유지한다. 블로그에는 자동 문서 탐색을 적용하지 않는다.

왼쪽 문서 목록과 오른쪽 이 글의 목차라는 별도 제목은 표시하지 않는다. 작은 화면에서 왼쪽 탐색을 여는 조작에는 분류 이름과 접근성 이름을 제공한다. 본문 목차는 접기 화살표·아이콘·외곽선 없이 항상 목록을 보인다. 오른쪽 목차는 렌더링된 H2·H3 제목을 사용하며 현재 절과 상위 절을 강조한다. 제목이 없으면 목차를 표시하지 않는다. 1040px부터 왼쪽 탐색 열이, 1300px부터 양쪽 탐색 열이 고정된다. 각 열은 독립 스크롤이다. 작은 화면에서는 본문 위로 이동하며 왼쪽 문서 탐색만 접는다. 중앙 영역은 최대 900px로 가운데를 유지하며, 오른쪽 목차는 200px 이상으로 화면 가장자리의 기본 여백까지 사용한다. 본문은 최대 680px, 넓은 블록은 양쪽 탐색과 겹치지 않는 중앙 공간 안에서 최대 900px다. 블로그 글은 양쪽 탐색을 사용하지 않는다.

`blog/`는 최초 발행일 최신순 본문 피드이며 네 편씩 이어 읽는다. `blog/all/`은 같은 글을 최신순 카드로 열두 편씩 읽는다. 다음 정적 페이지를 가져와 중복 없이 추가하고 마지막에는 멈춘다. 실패 시 더 보기로 재시도하고 JavaScript 없이도 원래 쪽 이동 링크를 사용한다. 새 본문에서 필요한 문서·영상·도표 모듈과 수식 스타일을 준비한 뒤 내용을 추가한다. 각 조작은 초기화한 요소를 중복 연결하지 않는다.

댓글 외곽 테두리와 회색 패널은 표시하지 않는다. 댓글은 본문 바탕에 두며 답글은 들여쓰기·얇은 구분선으로 구별한다. 입력창과 반응 버튼의 배경, 초점 표시와 서비스 권한은 유지한다.

블로그 썸네일은 목록 카드와 본문 피드·상세에서 같은 소스를 사용한다. 본문에서는 날짜 → 제목 → 소개 → 대표 이미지 → 본문 순서다. 대표 이미지는 기존 wide 역할로 900px까지 넓히고 원래 비율을 유지한다. 글의 읽기 폭은 680px를 유지한다. 카드에만 5:2 비율과 자르기 위치를 적용한다. 대체 설명을 재사용하며 상세 첫 이미지는 즉시, 목록·피드 이미지는 필요할 때 불러온다. 썸네일이 없으면 빈 영역을 만들지 않는다. Things 블로그 목록과 개별 글의 1280px 화면에서 680px 본문·900px 대표 이미지와 같은 순서를 직접 확인했다.

## 문서 파일과 공유 태그

프런트매터의 `category`는 내부 분류, `parent`는 부모 문서의 slug다. `tags`는 문서와 블로그가 공유하는 주제 목록이며 0~5개를 지정한다. 분류를 태그로 자동 복사하지 않는다. `id`는 댓글의 고정 식별자이고 `slug`는 공개 URL이므로 파일 이동으로 변경하지 않는다.

빌드는 `content/docs/`와 `content/blog/`의 하위 폴더를 재귀적으로 읽는다. 폴더와 부모 정보가 다르면 프런트매터를 따른다. 가져오기 도구는 부모 계층을 폴더로 표현하고 자식이 있는 문서는 해당 폴더의 index.md에 둔다. 다른 분류의 부모도 이어 붙인다. 공개되지 않은 부모는 사이트에 만들지 않고 해당 문서를 탐색 루트에 둔다. 순환 부모, 중복 식별자, 다른 문서가 이미 차지한 출력 경로는 오류다.

공개 원문을 다시 가져올 때 기존 문서의 slug·category·parent·tags는 보존하고 본문과 출처 해시를 갱신한다. 작성자가 직접 추가한 문서는 보존한다. 파일 경로와 출처는 발행 manifest에 기록한다. 카드 태그는 설명 아래 한 줄 요약이며 폭을 넘으면 말줄임한다. 각 태그는 카드의 글 링크 바깥에 둔 독립 링크이며 같은 주제의 문서와 블로그를 함께 찾는다. 다른 카드 영역은 글로 이동한다. 태그에 테두리를 두지 않고 회색 배경을 사용하며 호버·키보드 초점에서는 사용자가 지정한 재생 버튼과 같은 파랑 배경과 흰 글자로 카드 상태와 구별한다.

Tech 전체 보기 검증에는 example이 지정된 Kotlin·Docker 미리보기 문서 두 개를 사용한다. 미리보기 입구는 아홉 항목 중 여덟 개와 전체 보기 링크를 표시하며 전체 목록은 아홉 개를 표시한다. 운영 빌드는 두 문서와 해당 카드·검색 항목을 제외한다.

목록 이동 링크는 입구의 전체 보기, 전체 목록의 돌아가기·본문 이어 읽기, 피드 끝의 전체 글 보기 모두 같은 15px 글꼴과 파란색을 사용한다. 화살표 글자는 넣지 않고 공통 꺾쇠를 사용하며 돌아가기만 왼쪽이다. 태그는 본문·카드·검색 결과 모두 날짜와 같은 13px 칩으로 표시한다. 카드 말줄임표도 태그와 같은 크기와 줄 높이를 사용한다.

## 원문과 공개 승인

문서 원문은 별도의 비공개 자료 저장소에서 관리한다. `content/docs/`와 `content/blog/`의 Markdown은 공개 승인된 사본이며 직접 편집하지 않는다. 홈의 세 원고(`home.md`, `interviews.md`, `tech.md`)는 홈페이지에서 직접 편집한다. 승인 목록은 원문의 상대 경로와 SHA-256을 보관한다. 새 문서와 승인 이후 바뀐 내용은 명시적으로 다시 승인해야 가져올 수 있다. 인터뷰 원본과 검토 자료는 내보내기 경로에 포함되지 않는다. 비공개 원본의 `documents/wiki/`와 `documents/examples/` 문서는 `content/docs/`로, `documents/blog/`와 `documents/examples/blog/`는 `content/blog/`로 가져온다. 두 원본이 같은 공개 경로를 가리키면 쓰기 전에 중단한다.

```sh
npm run content:approve -- <assets-root> documents/wiki/os/index.md
npm run content:sync -- <assets-root>
npm run content:check
```

승인 해제는 같은 파일을 `content:revoke`에 지정한 뒤 동기화한다. 내보내기는 승인 해시와 공개 사본을 모두 검증한 다음 시작한다. 기존 발행 목록 읽기와 새 목록 생성도 공개 사본 쓰기 전에 끝내므로, 목록 해석 오류가 나면 사본과 승인 해시를 유지한다. 새 위키 항목의 `id`와 `slug`는 문서 식별자 형식을 만족하는 고유 문자열이어야 하며 항목 수와 무관하게 먼저 검사한다. 기존 공개 사본이 수동으로 바뀌었으면 덮어쓰거나 삭제하지 않고 중단한다. 승인되지 않은 파일, 경로 이탈과 심볼릭 링크도 거부한다. 공개 저장소에는 내보낸 파일과 검증용 해시만 남아 비공개 저장소에 접근하지 않고도 빌드할 수 있다. 빌드의 세 진입점이 모두 승인된 사본의 집합과 해시를 검사한다.

기존 공개 사이트를 가져오는 `import-publication.mjs`도 비공개 자료 루트를 두 번째 인자로 받는다. 이 명령은 자료 저장소의 documents/wiki와 imports만 갱신하며 홈페이지 승인 목록을 바꾸지 않는다. 가져온 뒤 검토와 승인을 거쳐야 홈페이지에 반영된다. 프런트매터가 주소와 계층의 기준이고 폴더는 작성 편의를 위한 구조라는 계약은 그대로다.

## 댓글 테마 배포

HTTPS origin이 있으면 댓글은 같은 공개 사이트의 `/theme/assets/giscus.css`를 디자인 해시 주소로 읽는다. origin이 없거나 HTTP인 미리보기는 공개 소비 저장소의 CSS를 jsDelivr의 HTTPS 주소로 읽는다. 빌드는 현재 CSS가 마지막으로 바뀐 Git 커밋을 찾아 파일 바이트를 대조하고 주소를 만든다. 특정 커밋을 코드나 설정에 고정하지 않으며 비공개 디자인 저장소의 주소를 사용하지 않는다.

공통 디자인 자동 전달은 내보내기와 의존성 설치 뒤 변경을 커밋하고 push한다. 홈페이지 검증은 이 push 뒤 실행되므로 바뀐 댓글 CSS도 커밋된 상태에서 주소를 계산한다.

미리보기의 CSS 주소를 직접 정하려면 `config/site.json`의 `comments.themeUrl`에 같은 공통 CSS를 제공하는 공개 HTTPS 주소를 지정한다. Git 이력이 없거나 CSS에 미커밋 변경이 있으면 명시한 주소가 필요하다. 외부 주소는 [giscus 사용자 테마 계약](https://github.com/giscus/giscus/blob/main/ADVANCED-USAGE.md#data-theme)에 따라 익명 CORS로 CSS를 제공해야 한다. 확인할 때는 공개 응답과 현재 CSS의 SHA-256, HTTP 상태·MIME·CORS 및 실제 iframe의 계산 스타일을 대조한다.
