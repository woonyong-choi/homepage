# 기록 탐색과 화면 구성

| 항목 | 값 |
|---|---|
| 상태 | 구현 |

## 요약

공개 글은 Blog 하나로 모은다. Search `/search/`에서 전체 글을 검색·태그로 찾고 Blog `/blog/`에서 최근 글 본문을 읽는다.

## 해결하는 문제

기술과 일상의 글을 별도 발행 체계로 나누지 않고 검색어와 태그로 찾는다. 폴더는 작성 편의용이며 URL이나 공개 계층을 정하지 않는다.

## 사용 예

### 사용 장면

홈의 Python 로고를 누르면 `/search/?tag=python`으로 이동한다. `산책` 태그를 누르면 같은 Blog에서 산책 글을 찾는다.

## 작동 방식

### 주소와 조건

| 주소 | 용도 |
|---|---|
| `/search/` | 전체 글 목록, 검색, 태그 필터 |
| `/blog/` | 최근 글 본문 피드 |
| `/blog/page/<번호>/` | 이전 글 본문 피드 |
| `/blog/<slug>/` | 글 상세 |
| `/blog/feed.xml` | RSS |

검색 조건은 `q`, 반복 가능한 `tag`, `page`로 URL에 저장한다. 예를 들어 `/search/?q=기록&tag=독서&tag=회고&page=2`는 검색어와 두 태그를 모두 만족하는 글의 둘째 페이지다. 여러 태그는 AND로 결합한다. 태그를 추가하거나 지우면 검색어와 나머지 태그를 유지하고 첫 페이지로 이동한다. 모든 조건을 지우면 Search 전체 목록이다.

공개 상단 탐색은 Search와 Blog다. Search는 전체 글의 목록·검색·태그 탐색이며 Blog는 같은 글의 최근 날짜순 본문 피드다. 별도 CS·Tech·Projects·위키 주제 목록과 부모 계층을 발행하지 않는다. `/docs/`, `/projects/`, `/tags/`, `/blog/all/`은 만들지 않는다. Blog의 다음 본문은 `/blog/page/<번호>/`로 이어 읽는다. 옛 주소를 인식하는 개인 미리보기 API와 공개 경로 생성은 별개다.

### 태그와 목록

태그는 등록 목록에 제한되지 않는 문자열이다. `python`, `산책`, `독서`, `회고`를 같은 필드에 쓴다. `config/tags.json`의 표시 이름과 별칭은 검색을 돕는 정보이며 새 태그의 승인 목록이 아니다.

Search 카드는 태그를 숨긴다. 검색창과 Search 제목 사이의 필터는 공통 `TagFilter` 토글을 사용한다. 본문은 공통 `TagList`를 사용한다. 본문 태그는 `medium` 크기이며 `/search/?tag=...`로 연결된다. 글의 장식 아이콘은 사용하지 않는다. 대표 이미지가 없으면 공통 제목 표지를 자동으로 표시한다. 검색·복사·재생·펼치기 조작 아이콘은 유지한다.

카드의 크기·열·간격·반응형·호버·초점은 공통 디자인 구성 요소가 소유한다. 홈페이지는 글과 표시 조건을 조립한다. 설정과 소유권은 [영역 설정](layout-settings.md), [스타일 수정 지도](styles.md)를 따른다.

### 개인 미리보기

개인 Vault 위키의 `category`, `parent`는 개인 호스트 계약으로 유지한다. 홈페이지의 개인 미리보기는 선택한 원고의 본문 목차만 조립하고 문서 계층 목록이나 이전·다음 문서 이동은 만들지 않는다. 공개 Blog에 이 계층을 합치거나 위키를 자동으로 Blog 글로 바꾸지 않는다. 외부 API와 승인 경계는 [개인 사이트 발행](publication.md#저장-전-페이지-미리보기)에 있다.
