# 기록 탐색과 화면 구성

| 항목 | 값 |
|---|---|
| 상태 | 결정된 탐색 구조, 세부 콘텐츠는 제안 |
| 추적 | [개인 레이아웃](https://github.com/woonyong-choi/homepage/issues/19) |

## 요약

Support형 화면을 통합 기록의 입구로 사용한다. 기술 기록의 분야는 Languages, CS, Frameworks, Infrastructure다. Blog는 같은 기록 중 발행한 글을 최신순으로 보여준다. 본문은 한 번만 저장하고 탐색 경로에서 연결한다.

## 동기

면접관은 대표 작업과 판단 근거를 먼저 찾는다. 학습 기록을 다시 찾는 방문자는 기술 이름과 개념으로 탐색한다. 중요도에 따른 입구와 주제별 탐색을 함께 제공한다.

## 예시

1. 방문자는 통합 입구의 Languages에서 Python을 선택한다.
2. Python 본문과 Python 문서 전체를 탐색하는 왼쪽 사이드바가 열린다.
3. 방문자가 Languages의 전체 보기를 선택하면 분야 전체 목록을 먼저 본다.
4. Blog에서 발행 글을 선택해도 같은 정본 본문으로 연결된다.

## 상세 설계

### 레벨과 사이드바

| 위치 | 역할 | 선택 결과 |
|---|---|---|
| 레벨 0 | 통합 기록의 입구, 분야마다 대표 카드 최대 6개 | Python 같은 카드에서 해당 주제 본문으로 바로 이동 |
| 레벨 1 | Show All로 여는 해당 분야의 전체 목록 | 주제를 선택하면 본문과 그 주제의 사이드바 표시 |
| 본문 | 주제별 문서와 왼쪽 사이드바 | 이후 문서 탐색을 사이드바 안에서 해결 |

사이드바 자체의 깊이는 0·1·2까지만 둔다. 페이지 레벨과 사이드바 깊이는 서로 다른 값이다. Python 사이드바는 Python 문서 전체를 대상으로 하되 하위 그룹은 펼치고 접을 수 있다. 본문마다 다시 카드형 중간 페이지를 거치게 하지 않는다. 모바일에서는 제목 위 문서 목록 버튼으로 펼치고 닫는다.

### 레벨 0 배치

| 영역 | 배치 | 선정 기준 |
|---|---|---|
| Languages | 3열, 최대 6개와 전체 보기 | Python·Kotlin 등 개별 언어 |
| CS | 3열, 최대 6개와 전체 보기 | 운영체제·네트워크·알고리즘 등 개념 |
| Frameworks | 3열, 최대 6개와 전체 보기 | 프레임워크와 라이브러리 |
| Infrastructure | 3열, 최대 6개와 전체 보기 | 데이터베이스·저장소·운영 기술 |
| Blog | 위키 입구 다음, 썸네일·제목·태그 카드 최대 3개 | 4개 이상부터 전체 보기 |

이 표는 Wiki 입구의 배치다. 항목 수가 적으면 빈 카드를 채우지 않고, 전체 보기는 숨은 항목이 있을 때 제공한다. 개발 프로젝트는 상단 Projects 목록에서 실제 도구와 관련 링크를 보여준다. 홈의 별도 포트폴리오 배열은 아래 영상·흐름 구성으로 대체했으며, 사용하지 않는 portfolio 설정은 제거했다. 같은 작업이 여러 탐색 경로에 등장해도 본문을 복제하지 않는다.

### 레벨 1 배치

주제의 전체 목록을 제공한다. 큰 카드는 설명이 필요한 대표 입구, 작은 설명 카드는 보조 주제, 제목 링크는 목적이 자명한 문서에 사용한다. 카드 크기를 문서의 품질 등급으로 쓰지 않는다. 분야 안의 세부 그룹과 대표 항목은 실제 문서 목록에 맞춰 정한다.

### 랜딩과 보존 영역

| 첨부 영역 | 결정 |
|---|---|
| 소개 | 로고 또는 이미지, 이름, 하는 일을 설명하는 문장 |
| 상단 메뉴 | Projects · Wiki · Blog. Blog는 본문 4편씩 연속 읽기 |
| 앱 파노라마 | 복각 검토 화면에 보존, 발행 홈에는 연결하지 않음 |
| Features | 복각 검토 화면에 보존, 발행 홈에는 연결하지 않음 |
| 뉴스레터 | 구성 요소 보존, 실제 전송 기능이 없어 초기 발행 화면에서 비활성화 |
| 푸터 | 이름과 로고, GitHub·RSS·검색 링크 |

메인은 개인 소개 → 진행 프로젝트 영상 → 기술 스택 흐름 → 인터뷰 흐름 → 메일 연락 → 푸터 순서다. 2026-10-08 사용자 요청에 따라 탐색용 목록은 Projects·Wiki·Blog 메뉴로 연결한다. 영상 파일이 없으면 영상 자리를 표시하고 재생 버튼은 만들지 않는다. 인터뷰는 미리보기의 명시된 예시와 실제 공개 원문을 구분한다. 기술은 오른쪽으로 흐르고, 인터뷰는 두 줄로 나뉘어 첫 줄은 왼쪽, 둘째 줄은 오른쪽으로 흐르며 시각 제목을 생략한다. 블로그 카드 전체 보기는 12편씩, 본문 연속 읽기는 4편씩 최신 발행순으로 제공한다. 상세 본문은 위키·블로그가 공통 글 주소와 렌더러를 공유한다. 태그·검색·댓글·발행 입력의 구현 계약은 [개인 사이트 발행](publication.md)에 있다.

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 네 분야 이름을 유지한다 | 메뉴·제목·전체 목록 대조 |
| 같은 글의 본문을 복제하지 않는다 | 통합 입구와 Blog의 문서 식별자 대조 |
| 사이드바 깊이가 2를 넘지 않는다 | 탐색 데이터 깊이 검사 |
| 미사용 앱 영역은 기능을 보존한다 | 설정에 따른 표시·숨김 확인 |

## 미해결 질문

- NAV-1과 NAV-3은 승인한 카드 수·순서·메뉴·모바일 문서 목록 계약으로 확정했다.
- NAV-2: 현재 공개 입력에서 AI·머신러닝과 시스템 설계는 CS에 연결한다. 관련 분야에서도 같은 문서 ID를 참조한다.
- 운영 발행 주소와 최종 디자인 차이의 수용 검증은 [통합 검증](https://github.com/woonyong-choi/homepage/issues/28)에서 추적한다.
