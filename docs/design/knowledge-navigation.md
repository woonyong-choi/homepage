# 기록 탐색과 화면 구성

| 항목 | 값 |
|---|---|
| 상태 | 구현 |

## 요약

Search는 문서와 블로그를 함께 찾는 입구다. CS는 지식 분류, Tech는 언어·도구별 목록을 보여 준다. 문서 계층과 태그로 탐색 범위를 좁힌다.

## 해결하는 문제

문서가 여러 분류에 걸치면 폴더만으로 탐색 관계를 표현하기 어렵다. 고정 ID·부모 관계·태그를 사용해 파일 이동과 탐색 구조를 분리한다.

## 사용 예

### 사용 장면

검색 결과에서 태그를 누르면 검색어를 유지한 채 해당 태그를 조건에 추가한다. 문서 하단의 이전·다음 링크는 같은 주제의 탐색 순서를 따른다.

## 작동 방식

### 입력과 구성

Search는 블로그와 문서를 함께 찾는 입구다. CS는 11개 최상위 지식 분류, Tech는 언어·도구별 목록이다. 내부 `category`는 문서 탐색을 위한 값이고 태그는 문서와 블로그가 공유한다.

### 분류

최상위 분류의 순서, 전체 이름, 아이콘과 입구 문서는 [기술 원고](../../content/pages/tech.md)의 `topics`에서 관리한다. 수학·컴퓨터 과학 기초부터 보안·개인정보 보호까지 11개 분류를 사용하고 ML과 LLM의 기존 분류 값은 인공지능으로 연결한다. 문서 원문의 분류, 고정 ID, URL과 공개 범위는 바꾸지 않는다.

발행 시 문서 자체 또는 같은 원문 분류의 가장 가까운 공개 부모가 분류 입구이면 그 분류를 탐색에 적용한다. 입구를 찾지 못하면 원문의 분류 값과 `topics.<id>.topic` 참조를 사용한다. 목록과 문서 탐색은 이 결과를 함께 사용하므로 인공지능 입구와 딥러닝, 기존 ML·LLM 문서가 같은 탐색에 연결된다.

### 계층

문서의 고정 ID와 `category`, `parent`가 문서 체계를 정한다. 폴더는 사람이 찾아보기 좋도록 같은 계층으로 둘 수 있지만 빌드가 폴더 위치로 부모나 URL을 추측하지 않는다. 공개 위키 문서 전체에서 parent를 연결하며 다른 category의 부모도 유지한다. 각 category의 탐색에는 해당 분류의 문서를 포함한 루트 트리를 중복 없이 넣는다. 부모가 미발행이거나 블로그이면 자식은 최상위에 놓고, 부모 순환은 빌드 오류로 거부한다.

### 목록

| 화면 | 넓은 화면의 열 수 |
|---|---|
| Search의 블로그 미리보기 | 2 |
| 전체 블로그 | 3 |
| Search의 CS 미리보기 / 전체 CS | 3 / 4 |
| Search의 Tech 미리보기 / 전체 Tech | 4 / 5 |

전체 목록은 공통 넓은 콘텐츠 폭을 쓴다. 검색 입력은 읽기 폭을 유지한다. 제목 아래의 돌아가기와 본문 이어 읽기, 목록 아래 전체 보기는 같은 NavigationLink를 쓰며 개수 설명은 표시하지 않는다. 기본 설정은 블로그 3열, CS 4열, Tech 5열이다. [영역 설정](layout-settings.md)에서 문구, 영역과 주제 순서, 미리보기·전체 목록의 열·행 수, 카드 표시 항목을 바꿀 수 있다. 긴 제목은 전체 이름을 유지하고 가용 폭에서 자연스럽게 줄바꿈한다. 작은 화면은 공통 카드의 반응형 배치를 사용한다.

### 검색과 태그

태그를 누르면 현재 검색어를 유지하고 태그 조건을 추가한다. 여러 태그는 AND이며 검색어와 태그도 AND로 적용한다. 선택 조건에서 개별 태그를 지우거나 전체 조건을 초기화한다. 태그는 검색 결과·카드·본문에서 같은 TagList를 쓴다. 카드와 태그의 링크는 각각 작동한다.

블로그는 카드 목록과 본문 이어 읽기를 제공한다. 문서와 블로그 모두 도입문 다음에 태그를 표시한다. 작성자 표시는 댓글 안에서 유지한다.
