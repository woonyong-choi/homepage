# 화면 검증

## 최종 검증 범위

새 페이지 증설을 중단하고 기존 대표 화면과 전체 문법 예제의 디자인·동작을 검증했다. 원문 대신 합의한 한국어 예시 본문을 사용한다. 아래의 개별 작업 기록은 수정 당시의 관측이며, 후속 수정으로 해소된 차이는 최신 기록을 따른다.

- 현재 테마 해시: `fd2b4bd64ef3ee338d4b46d9df733329cef5316eeef90252915ab715648c541c`
- 외부 미리보기의 홈·기능·지원 목록·Siri 지원 상세·블로그 목록·블로그 상세를 390px와 1440px에서 열었다. 모두 최신 테마를 로드하고 각각 문서 폭/스크롤 폭 375px와 1425px가 같았다. 로드 완료 이미지 오류는 없었다.
- 문법 예제는 등록된 구성 요소 23종, 지원 아이콘 31종, 인라인 키캡과 메뉴, 일반 Markdown을 포함한다. 파서 검사는 구성 요소 누락, 이스케이프, ID·각주, 슬라이드 초기 상태를 검사한다. 실제 화면에서는 아이콘·표·코드·탭·카드·캡션·폼을 확인했다.
- 첨부 토큰·변수 CSS·테마 CSS·디자인 문서 4개는 reference 파일과 바이트가 같다. base/simple 상속, 생성물·사본 해시, CSS 토큰 검사로 정본 연결을 확인했다.
- 영상 제어·슬라이드·플랫폼 탭·검색·폼의 실행 근거는 아래 동작 검증 절에 있다. 해당 동작 소스는 마지막 검색 오류 수정 이후 변경되지 않았다.
- 예시 문장과 원문의 글리프·줄바꿈, 실제 외부 전송, 전체 아카이브 내용은 동일성 판정 대상이 아니다. 확인한 화면과 상태를 넘어 모든 브라우저·모든 화면 폭의 픽셀 동일성을 주장하지 않는다.

## 비교 대상

- 원본: https://culturedcode.com/things/ 및 support, features, blog
- 구현: 로컬 정적 서버의 /things/ 이하
- 지원 첫 화면: 두 탭 모두 CSS 1440×1000, devicePixelRatio 1로 맞추고 한 번의 비교 입력에서 두 캡처를 함께 확인했다.
- 모바일: CSS 390×844에서 문법 문서·지원 목록·슬라이드를 확인했다.

## 수정한 차이

| 차이 | 수정 | 재확인 |
|---|---|---|
| 홈 아이콘과 이름이 원본보다 큼 | 이미지 표시 폭을 300에서 실측 250px로 변경 | 홈 화면 |
| 홈 소개의 폭과 줄 높이 차이 | 440px, 1.25 비율로 변경 | 홈 화면 |
| 지원 카드 아이콘이 작음 | 카드 안 스프라이트를 실측 48px로 변경 | 수정 후 지원 첫 화면 비교 |
| 첫 카테고리와 카드 간격 차이 | 검색 아래 공간, 제목 아래 간격, 첫 카드 최소 높이 조정 | 수정 후 지원 첫 화면 비교 |
| Cloud 대표 카드와 짧은 링크의 배치 차이 | 대표 카드 옆에 링크 네 개를 묶음 | 생성 HTML과 지원 목록 |
| 기본 사이트 토큰 감사가 참고 자산을 수정 대상으로 판정 | 참고 자산을 해시로 보존 검증, dist는 생성물 검사로 분리 | 기존 사이트 빌드 통과 |

| 휴대폰 이미지가 본문 전체 폭으로 확대됨 | 실제 프레임·설명과 미디어의 2열 배치 적용 | 외부 페이지에서 프레임 371px, 화면 281.0625px, 넘침 없음 확인 |

## 필수 시각 항목

- 글꼴: simple에서 첨부와 원본 기준 시스템 글꼴로 재정의했다. 베이스 글꼴은 변경하지 않았다.
- 배치: 지원 본문 680px, 확장 미디어 900px, 두 칸·세 칸 카드, 긴 글 피드 구조를 적용했다.
- 색과 토큰: simple 테마의 역할 변수로 사용한다. 첨부 참고값과 원본 실측값을 테마에 정의했다.
- 이미지: 로컬 원본 자산과 아이콘 스프라이트를 사용했다. 임의 그림으로 대체하지 않았다.
- 콘텐츠: 한국어 더미 내용으로 원문과 문단 길이가 다르다. 전체 문법 페이지는 의도적으로 예시가 많아 원본보다 길다.

## 동작 확인

검색에서 Markdown 문서로 이동, 기기 탭 전환, 독립 슬라이드 전환과 방향키, 홈 영상 재생, 모바일 가로 넘침 없음, 외부 미리보기의 코드 복사와 데모 폼 검증, 화면의 콘솔 오류 없음까지 확인했다. 자동 검사는 URL 안전성, 중첩 구성 요소 ID·각주, 잘못된 문법 실패, 전체 문법 렌더링을 검사한다.

## 판정

지원 문서와 문법을 검토할 수 있는 구현이다. 지원 화면의 큰 배치·아이콘·여백 차이는 수정 후 재비교했다. 모든 원본 페이지와의 픽셀 단위 일치 판정은 하지 않았다. 플랫폼·회사·소셜 페이지는 공통 문서 레이아웃의 더미이며, 외부 서버 기능은 데모 입력으로 제한된다. 개인 사이트 정보 설계는 다음 작업이다.

## 동작·반응형 재검토

원본의 shared.min.js, shared.css, things.css, support.min.js, support.css와 브라우저의 실제 상태를 대조했다.

- 소개 영상: 재생 전 숨김, 재생 후 표시, Play/Pause/Replay 아이콘, 거리 비례 스크롤(1600px/s, 최대 1000ms, swing 곡선, 50px 여유)을 연결했다. 브라우저에서 재생 및 일시정지 상태를 확인했다.
- 기능 영상: 무음 인라인 재생과 별도 Play 버튼을 연결했다. Magic Plus는 세 개의 탭 대신 하나의 기기 플레이어와 세 재생 버튼으로 변경했다. 두 번째 버튼 클릭 후 실제 src가 6-magicplus-2.mp4로 바뀌고 해당 버튼만 Pause 상태인 것을 확인했다.
- 갤러리: 겹친 패널의 visibility를 전환해 모든 패널이 높이 계산에 참여한다. 블로그 첫 갤러리는 1→2 전환 전후 높이 558px을 유지하고 선택된 패널은 한 개였다. 원본처럼 별도 페이드 전환은 없다.
- 지원 카드: hover의 120ms 이동·그림자, active 배경을 반영했다. 390px 화면에서 폭 345px의 한 열 목록과 왼쪽 아이콘을 확인했다. 더미 본문의 줄바꿈 때문에 카드 높이는 원문과 다르다.
- 후기: 740px 미만에서는 Show More Posts로 목록을 누적한다. 모바일에서 두 묶음이 함께 표시되는 것을 확인했다. 큰 화면에서는 이전/다음으로 교체하며 끝에서 순환하지 않는다.
- 검색: 250ms 입력 대기, 한 글자 안내, 아이콘·제목·설명, hover/active 상태를 추가했다. Markdown 검색으로 해당 내부 문서가 표시되는 것을 확인했다. 검색 대상은 로컬 더미 문서이며 원본 서버의 검색 순위와 같다는 의미는 아니다.
- 지원 문서의 platform 문법을 별도로 추가했다. ?platform=iphone으로 iPhone & iPad가 선택되는 것을 확인했다. 이후 플랫폼 블록에도 선택을 전달한다.
- 제품·지원 목록·기능 설명·푸터에 각각의 반응형 분기점을 적용했다. 390px 홈에서 모든 자원 로드 후 가로 넘침이 없음을 확인했다.
- 스타일과 동작 값의 정본은 design-tokens/themes/base/simple이며 블로그에는 검증된 내보내기만 반영했다.

### 남은 일치 범위

100% 일치로 판정하지 않는다. 더미 본문의 줄바꿈, 모든 내부 페이지의 고유 배치, 후기 카드 높이와 전체 페이지의 픽셀 비교는 아직 완전 일치가 검증되지 않았다. 빌드 성공과 동작 검증은 전체 사이트의 시각적 동일성을 증명하지 않는다.

- simple의 글꼴은 이번 첨부 파일과 원본의 시스템 글꼴 계열로 재정의했다. 베이스의 font.sans 값은 변경하지 않았다. 첫 기능 영상은 브라우저에서 원본과 같은 640px 폭으로 확인했다.


## 홈·기능·블로그 실측 재검토

1440×1000과 390×844의 같은 브라우저 viewport에서 원본과 외부 미리보기를 대조했다. 이전 CSS가 캐시에 남아 새 HTML에 오래된 배치가 적용되는 문제를 발견하여 테마·스크립트 해시를 자산 URL에 반영했다.

- 홈: 1440px에서 큰 이미지 시작점은 원본 716.41px, 구현 716.50px이었다. 기능 소개 섹션 높이는 모두 1386.78px이었다. 후기의 데스크톱 4×2 배치, 모바일 2열 누적 표시, 제품 배경 이미지, 인용문 말풍선, 소셜 SVG와 뉴스레터를 다시 구성했다.
- 모바일 홈: 390px에서 로고 폭 232.875px과 높이 279.906px을 원본과 동일하게 확인했다. 더 보기 클릭 후 두 후기 묶음이 동시에 표시되며 가로 넘침이 없었다.
- 기능: 14개 소개 섹션과 마지막 블로그 연결, 8개 세부 기능 목록을 렌더링한다. 제품·후기는 홈 데이터에서 재사용한다. iOS 탭 선택과 실제 영상 재생 15.55초 진행, 일시정지를 브라우저에서 확인했다.
- 지원: 검색 아이콘을 원본의 32px 표시 폭으로 수정했다. 모바일 추천 검색어는 80% 폭에서 줄바꿈한다. 카드 제목과 본문 사이 간격, 글자색을 실측값으로 변경했다.
- 블로그: 본문 680px와 확장 이미지 900px을 유지하며 긴 글 구조를 구성했다. 대화 슬라이드는 클릭 1→3, 방향키 3→4 전환과 선택 상태를 확인했다. 본문 이미지는 깨진 항목이 없었다.

위 기록은 해당 화면과 동작의 확인 결과다. 모든 내부 페이지의 고유 레이아웃과 모든 viewport를 확인했다는 뜻은 아니다. 더미 문단의 언어·줄바꿈은 원문과 다르며 목표 작업은 계속 진행 중이다.

## 내부 페이지와 모바일 보완

- 지원 상세 검색창의 상단 여백·높이·모서리와 제목을 실측했다. 1440px에서 제목 시작점 223.81px, 높이 59.58px를 확인했다. 원본에 없는 자동 목차를 제거하고 전체 문법 예시는 별도 경로로 옮겼다.
- 블로그 확장 이미지의 가로 넘침을 수정했다. 검사는 `innerWidth` 대신 `documentElement.clientWidth`와 `scrollWidth`를 비교한다. 390px viewport에서 둘 다 375px인 것을 확인했다.
- 문의 양식의 라디오·체크박스는 실제 SVG 자산을 사용한다. 로컬 검증 확인 후 전송 버튼이 활성화되고, 제출 시 외부 전송 없이 결과를 표시하는 것을 브라우저에서 확인했다.
- 뉴스레터 입력 검증과 결과 표시를 확인했다. 소개·채용은 일러스트와 반투명 패널로 구분하고, 법적 문서는 더미 본문과 제목 계층을 사용한다.
- 기능 페이지의 세 가지 알림 설명과 보충 문단, 네 가지 목록 편집 설명, 재생 버튼 위치, 두 열 목록의 세로 순서를 수정했다. 390px에서 기능 14개와 가로 넘침 없음, 누락 이미지 없음을 확인했다. 공유 플레이어는 두 번째 영상을 선택하여 실제 재생 8.61초 진행과 선택 버튼만 일시정지 상태가 되는 것을 확인했다.
- 상태 화면, 보도 자료의 검토용 ZIP 다운로드, 생산성 가이드의 내부 이동을 추가했다. 이 화면들의 모든 시각 상태는 아직 대조 완료가 아니다.

미검증 상태와 전체 사이트 동일성은 위 개별 검사 결과로 대체하지 않는다. 목표는 계속 진행 중이다.

## 홈 높이와 추가 상호작용 확인

- 768px viewport: 제품 섹션 906.9375px, 후기 섹션 985.6875px로 원본과 동일하게 측정했다. 제품 배지의 고정 높이가 좁은 카드에서 비율을 깨뜨리는 문제와 소셜 SVG의 기준선 차이를 수정했다.
- 1440px viewport: 기능 섹션 1386.78125px, 제품 887.25px, 후기 985.6875px, 푸터 303.0625px로 원본과 동일했다. 도입부는 0.09375px 차이가 있으며, 더미 인용문·뉴스레터의 전체 높이는 완전 동일하지 않다.
- 상태 보드: 상단 시작점 331px, 상태 영역 높이 100px를 원본과 동일하게 확인했다. 과거 기록 버튼은 `aria-expanded`와 문구가 함께 바뀌며 패널을 펼친다.
- 전체 문법 페이지: 29개 복사 버튼, 2개 갤러리, 2개 입력 양식, 표·탭을 확인했다. 첫 JavaScript 코드의 실제 클립보드 내용과 `Copied` 표시를 확인했다. 390px viewport에서 clientWidth/scrollWidth가 모두 375px였다.
- 단축키 문서: 13개 그룹의 표와 27개 언어 선택 옵션을 Markdown으로 제공한다. Korean 선택 시 설정된 예시 키가 바뀌고, 도움말 팝오버가 열리고 Escape로 닫히는 것을 확인했다. 390px에서 가로 넘침이 없었다.

- 도움말은 원본처럼 클릭으로 여는 팝오버로 변경했다. 데스크톱에서 277.5px 폭, 열림 상태, Escape 닫기를 확인했다. 화면 아래에 공간이 없으면 위쪽을 선택하고 스크롤 시 닫는다.

## 외부 미리보기 영상 구간 요청

- 공개 미리보기의 Python 정적 서버가 Range 요청에 전체 파일인 HTTP 200으로 응답했다. 재생은 됐지만 탐색 막대를 옮겨도 실제 시간이 이동하지 않았다.

## 인라인 키캡과 검색 초점

- Markdown Guide의 단축키가 일반 코드로 표시되던 차이를 수정했다. `:kbd[...]`와 `:menu[...]` 문법으로 문장 안 키캡과 메뉴 이름을 표현한다. 기존 블록 키캡도 유지한다.
- 브라우저에서 키캡의 14px 글자·22.375px 높이, 메뉴 이름의 600 굵기·18px 글자를 확인했다. 390px에서 문서 폭과 스크롤 폭은 모두 375px이었다.
- 원본과 구현의 검색 초점 그림자는 rgb(100,159,255) 0 0 0 3px로 같았다. 기존 전역 초점선과 중복하지 않는다.
- 문법 검사는 7개로 늘었다. 인라인 문법의 HTML 이스케이프, 코드 구간 보존, 역슬래시 이스케이프를 검사한다.

## 플랫폼 탭의 입력 방식 일관성

- 방향키·Home·End 전환이 클릭과 달리 후속 플랫폼 블록에 선택을 전달하지 않던 문제를 수정했다. 키보드도 동일한 클릭 선택 처리를 사용한다.
- 문법 예제에 두 번째 플랫폼 블록을 추가했다. 첫 블록에서 ArrowRight 입력 후 두 블록 모두 iPhone & iPad가 선택되고 모바일 본문이 표시됐다. 두 번째 블록에서 Home 입력 후 첫 블록은 iPhone & iPad를 유지하고 두 번째만 Mac으로 바뀌었다.
- 별도 일반 탭은 Overview를 유지했다. 플랫폼 연동과 독립 탭의 상태가 섞이지 않음을 확인했다.

## 320px 화면과 내비게이션 분기

- 홈·기능·지원·블로그·문의·문의 양식·뉴스레터·상태·소개·가격의 10개 대표 화면을 320px viewport에서 검사했다. load 완료 후 모두 clientWidth/scrollWidth 305px이며 로드 완료 이미지의 오류는 0개였다. 화면 밖 lazy 이미지 전체의 로드 검증을 의미하지 않는다.
- 내비게이션을 원본의 inline-block 항목과 공백 구조로 변경했다. 620px 이하는 14px, 340px 이하는 13px 글자를 쓰며 작은 화면의 항목 좌우 여백은 2px이다. 기존 일반 링크·키보드 이동을 유지한다.
- Features 링크 시작점은 390px에서 원본·구현 모두 153.71875px, 1440px에서 모두 946.984375px였다. 320px과 700px은 외곽 컨테이너의 반올림으로 0.015625px 차이가 남고, 링크의 폭·높이와 y=27px는 같다.

## 소개·채용 패널

- 원본 소개·채용 페이지와 1440px·390px에서 비교했다. 이메일 버튼을 기존 공통 버튼 역할 토큰에 연결해 배경 rgb(207,216,230), 16.56px·600 글자, 6.9552px/16.56px 패딩, 7.452px 모서리를 일치시켰다.
- 소개·채용의 첫 문단은 22.5px, 연락처 패널은 `lead: false`로 18px를 사용한다. 패널 마지막 문단의 25.2px 아래 여백과 제목·본문 색을 복구했다.
- 일러스트 위 헤더에 원본의 rgba(255,255,255,.6) 배경을 적용했다. 그림은 원본 크기와 위치를 유지하며 헤더의 배경은 하단 구분선까지만 표시된다.
- 390px에서 clientWidth/scrollWidth 375px을 확인했다. 더미 문단 길이에 따른 패널 높이 차이는 남으며 원문 복제는 하지 않는다. 문법 7개·테마 25개 검사와 CSS 하드코딩 0건을 확인했다.

## 공통 본문과 내비게이션 상태

- 본문 색은 원본의 rgb(48,51,54)에 맞춰 기존 ink 원시 토큰을 재사용한다. 메뉴 기본 글자는 불투명 회색 대신 rgba(38,52,74,.5)를 사용해 흰 배경과 색이 있는 배경에서 원본과 같은 합성을 유지한다.
- 실제 포인터 입력으로 원본과 구현의 hover 글자 rgba(38,52,74,.7), 배경 rgba(4,15,26,.05)를 확인했다. 누르는 동안 글자 rgba(4,15,26,.7), 배경 rgba(4,15,26,.1), transform scale(.98)가 같았다.
- 홈 로고는 hover 시 opacity 1과 background-position 4px 0px로 바뀐다. 어두운 상태 화면의 로고 배경은 별도 상태 토큰을 사용한다.

## 검색 실패·복구와 폼 재검토

- 없는 검색어 입력 후 빈 결과 안내, Clear 후 숨김을 확인했다. 브라우저에서 검색 색인 요청을 차단해 실패 안내를 확인한 뒤 차단을 해제하고 Cloud 재검색으로 결과가 복구됐다. 검증 후 네트워크 설정을 원상복구했다.
- 이전 요청 실패가 최신 입력의 안내를 덮지 않도록 요청 세대를 확인한다. 5초 지연 중 Markdown에서 한 글자 x로 바꾸고 오프라인 상태를 적용했을 때 Keep typing 안내를 유지했다. 검증 후 지연·오프라인 설정을 해제했다.
- 문의 폼은 확인 체크 전 버튼이 비활성이고, 잘못된 이메일은 typeMismatch로 제출되지 않았다. 올바른 예시 이메일을 입력한 뒤에는 외부 전송 없이 검토 완료 안내를 표시했다.
- 문법 검사 7개와 기존 사이트 빌드를 다시 실행했다. 309개 문서 빌드, 824개 파일과 310개 페이지 검사에서 오류가 없었다.

## 공통 색 변경 후 대표 화면 재대조

- 1440px에서 홈 여섯 섹션 높이는 1134.65625, 1386.78125, 887.25, 985.6875, 2667.09375, 619.34375px로 원본과 같았다. 푸터도 303.0625px로 같았다.
- 소개·섹션 설명은 일반 본문과 다른 rgb(68,71,75)여야 하므로 기존 원시 값을 설명 역할에 연결했다. 일반 본문은 rgb(48,51,54)를 유지한다.
- 기능 페이지의 흰 헤더 띠를 제거하고 히어로와 같은 rgb(213,217,222)를 연결했다. 미디어 크기는 유지하며 더미 소개 문단 줄 수에 따른 시작점 차이는 남는다.
- 390px 지원 추천어의 0.05em 좌우 패딩과 rgba(0,5,11,.64) 색을 맞췄다. 각 항목 폭은 51.375, 80.125, 69.25, 54.296875px로 원본과 같다.
- 모바일 블로그의 헤더 아래 경계는 원본·구현 모두 360.21875px였다. 첫 확장 이미지는 390×243.53125px이며 로드 후 원본과 같은 화면 구성을 확인했다.
- 구독 버튼 hover는 원본과 구현 모두 rgb(100,159,255), opacity 1, 0 2px 4px rgba(0,0,0,.05) 그림자다. 눌림·초점 역할도 공통 원본 규칙으로 연결했다.
- 수정 후 문법 7개·테마 25개 검사, 생성물 28개 검사, 기존 309개 문서 빌드와 310개 페이지 검사 및 CSS 하드코딩 0건을 확인했다.

## 컨테이너 반올림과 검색창 높이

- 원본 CSS의 content-box 컨테이너와 좌우 4% 안전 여백을 확인했다. 기존 92% 폭 지정 대신 같은 토큰에서 좌우 여백을 계산하도록 변경했다. safe-area-inset도 반영한다.
- 검색창의 세로 패딩을 0.5em으로 계산하고 글자 크기의 소수점 절삭을 제거했다. 320/390/700/1440px에서 입력창 폭·높이와 메뉴 x 좌표가 원본과 같았다. 검색창 높이는 53.78125px이다.
- 1440px 홈 여섯 섹션과 푸터의 높이는 앞선 원본 대조값을 유지했다. 390px 문법 예제는 clientWidth/scrollWidth 375px이고 로드 완료 이미지 오류는 없었다.
- 말풍선 꼬리와 출처 로고·실제 글자 영역의 경계를 320/390/700/1440px에서 검사했다. 각 폭의 카드 13개 모두 교차와 출처 영역 가로 넘침이 없었다. 이 결과는 현재 예시 콘텐츠에 대한 검사다.
- 문법 7개·테마 25개 검사, 생성물 28개 검사, 기존 문서 빌드와 CSS 하드코딩 검사를 통과했다. 새 페이지는 추가하지 않았다.

## 헤더 경계와 문법 화면 재확인

- 원본 내비게이션의 하단 그림자는 rgba(38,52,74,.15)이며 y=68px에서 시작한다. 기존 불투명 경계를 별도 역할 토큰으로 변경하고 1px 위에 있던 위치를 수정했다. 상태 페이지의 별도 경계 색은 유지한다.
- 최신 외부 미리보기에서 데스크톱 지원 아이콘 31종과 독립 탭을 확인했다. 390px 표·코드 블록 화면에서 버튼이 본문을 덮지 않고 clientWidth/scrollWidth가 375px임을 확인했다.
- 첨부 토큰·변수·테마·디자인 문서 4개와 reference 원본의 바이트 동일성을 대조했다. 테마 25개·문법 7개 검사와 생성물 28개 검사, CSS 하드코딩 0건을 확인했다.

## 개발자 도구의 검색 소스 대조

- 브라우저에 로드된 shared.css·support.css의 CSSOM과 support.min.js를 읽고 원본 DOM·계산된 스타일·입력 상태와 대조했다. 검색 데이터와 본문은 합의한 로컬 예시를 유지한다.
- 지우기 버튼은 지원 목록에서 42×45.78125px, 반지름 8.5px이다. 실제 포인터의 hover 배경 rgba(0,0,0,.08), 눌림 배경 rgba(0,0,0,.16)가 원본과 같았다. 클릭 후 입력과 결과가 비워지는 것을 확인했다.
- 원본에 있는 결과 행 사이 1px rgba(0,19,48,.06) 경계와 12×18px 화살표, 0.2 투명도를 추가했다. hover 시 현재 행과 다음 행 경계를 숨기고 0.5em 모서리를 적용한다.
- 단순 텍스트였던 검색 안내를 별도 DOM으로 변경했다. 한 글자 입력 안내·빈 결과 아이콘·로딩·실패 안내가 같은 구성 요소를 사용한다. 390px에서 원본과 17px 글자, 23.8px 줄 높이, 17px/34px 패딩, 최대 340px 내용 폭과 색이 같았다. 예시 문장 길이에 따른 줄 수는 다르다.
- 검색 실패의 요청 세대 확인과 HTML 이스케이프를 유지했다. 검색어 지우기와 빈 결과에서 Cloud 결과로의 복구, 375px 문서 폭/스크롤 폭 일치, 브라우저 콘솔 오류 없음을 확인했다.
- 문법 7개·테마 25개 검사와 생성물 검사, CSS 하드코딩 0건을 통과했다. 이 절은 검색 구성 요소의 소스 정합 근거이며 전체 사이트의 모든 소스가 동일하다는 의미는 아니다.
